order owns a customer's cart and every order from checkout until it is completed, cancelled or returned.
It owns no price, no stock and no money. At checkout it asks the services that do, records their answers,
and coordinates the steps that reserve and charge — so most of what order gets right is knowing which
facts are not its own.

## How a checkout runs

A checkout is a sequence of questions, each to the service that owns the answer, and then a saga that
holds what was agreed:

1. **The cart** is read from Redis. The prices in it are not trusted: order asks catalog for each product
   again, because a cart can be fourteen days old — see
   [Never trust a number the client can type](/learn/trust-boundaries/).
2. **The merchant** catalog names for the cart must still be allowed to sell: order
   [asks identity](https://github.com/WildanFrananda/kinetix-order-service/blob/47f3a62482646bb5e43957fd44000eed39f608ed/Application/Services/OrderService.cs#L65-L67)
   at every checkout, and refuses with `409` when it may not and `503` when identity cannot say.
3. **Shipping** is quoted by matching and priced by pricing, and **the total** comes from pricing. If
   pricing cannot be asked, the checkout is refused with `503` rather than charged at a remembered price —
   see [Unknown is not no](/learn/unknown-is-not-no/). The voucher the order records is
   [the one pricing applied](https://github.com/WildanFrananda/kinetix-order-service/blob/47f3a62482646bb5e43957fd44000eed39f608ed/Application/Services/OrderService.cs#L84), not the code the buyer typed, so a voucher pricing refused is never
   redeemed. Each item is recorded at
   [the price pricing charged for that line](https://github.com/WildanFrananda/kinetix-order-service/blob/47f3a62482646bb5e43957fd44000eed39f608ed/Application/Services/OrderService.cs#L216-L253),
   flash sale included, and the checkout is refused if pricing left a line out or its lines do not add up
   to its subtotal — a return is refunded from these amounts, so they have to be what was paid.
4. **The saga** then reserves stock, redeems the voucher, allocates flash-sale stock and holds the money
   in escrow, recording each step before it calls and compensating newest-first when one is refused — see
   [The checkout saga](/learn/checkout-saga/).

An `Idempotency-Key` header makes a retried checkout return the first order instead of creating a second
— see [The same request, twice](/learn/idempotency/).

## When the merchant is paid

The buyer's money stays in payment's escrow until order says the order is complete. An order is
[completed](https://github.com/WildanFrananda/kinetix-order-service/blob/47f3a62482646bb5e43957fd44000eed39f608ed/Application/Completion/OrderCompletion.cs#L93-L141)
once it has been delivered, its return window has closed — seven days from the time the courier reported
the delivery, set by `KINETIX_RETURN_WINDOW_DAYS` — and no return against it is still open or waiting for
its refund. Only then does order ask payment to release the escrow to the merchant.

Completing an order and opening a return both
[lock the order's row](https://github.com/WildanFrananda/kinetix-order-service/blob/47f3a62482646bb5e43957fd44000eed39f608ed/Application/Completion/OrderCompletion.cs#L33)
before they read it, so a return cannot be opened against an order whose money is being paid out, and a
completion that waited behind a new return sees it. The order becomes `COMPLETED` first and the release
is then owed: if payment cannot be reached it is
[retried with backoff](https://github.com/WildanFrananda/kinetix-order-service/blob/47f3a62482646bb5e43957fd44000eed39f608ed/Application/Completion/OrderCompletion.cs#L143-L165),
and if payment refuses, it stops and waits for a person rather than retrying forever.

## Returns

A return is opened by the merchant through warehouse, and only against a delivered order; a completed
order's window has closed. When the goods come back, every line must
[name an item of the order and no more than was bought](https://github.com/WildanFrananda/kinetix-order-service/blob/47f3a62482646bb5e43957fd44000eed39f608ed/Application/Returns/ReturnsHandler.cs#L215-L231).
The buyer is refunded
[the share of the merchant's money those goods were worth](https://github.com/WildanFrananda/kinetix-order-service/blob/47f3a62482646bb5e43957fd44000eed39f608ed/Application/Returns/ReturnsHandler.cs#L195-L213)
— the order's total less its shipping fee, times the returned value over the value of everything bought,
rounded down to the cent — so a voucher is shared out with it, a full return refunds the merchant's whole
share, and the courier keeps the fee for a delivery that was made. The refund is paid from the escrow
under the key
[`return:{return number}`](https://github.com/WildanFrananda/kinetix-order-service/blob/47f3a62482646bb5e43957fd44000eed39f608ed/Application/Returns/ReturnRefunds.cs#L21),
so a retry cannot pay it twice.

## How the code is laid out

| Directory | Holds |
| --- | --- |
| `Controllers/` | the HTTP surface: cart, checkout, orders, saga administration, health |
| `Application/` | the checkout saga, the order and cart services, delivery, completion and returns |
| `Application/Ports/` | the interfaces the application needs — [one per collaborator](https://github.com/WildanFrananda/kinetix-order-service/tree/47f3a62482646bb5e43957fd44000eed39f608ed/Application/Ports), such as `IPricingClient` and `IStockClient` |
| `Infrastructure/` | what implements those ports: gRPC clients and the gRPC server, EF Core persistence, background workers, observability |
| `Domain/` | entities and enums, with no framework code |
| `Security/` | service identity on the mesh, caller allow lists, token validation |

The application depends on its ports, not on gRPC: the checkout saga is tested with fakes of
`IPricingClient` and `IStockClient`, while `Infrastructure/Grpc/` is the only place that knows a
collaborator is a remote service.

## Data

PostgreSQL, through EF Core, holds
[orders and their items, checkout sagas and their steps, compensation attempts, the shipping fees owed to
couriers, the escrow releases owed to merchants, and returns](https://github.com/WildanFrananda/kinetix-order-service/blob/47f3a62482646bb5e43957fd44000eed39f608ed/Infrastructure/Persistence/OrderDbContext.cs#L9-L17).

Redis holds carts, one per customer under
[`cart:principal:{principal id}`](https://github.com/WildanFrananda/kinetix-order-service/blob/47f3a62482646bb5e43957fd44000eed39f608ed/Application/Services/CartService.cs#L12-L14),
expiring fourteen days after the last change. A cart is the only thing order keeps outside its database,
and nothing in it is believed at checkout.

## Who may do what

- **Customers** reach the cart and orders through the gateway with an access token — only an access
  token, never the refresh or two-factor token signed by the same key; see
  [Tokens that can be taken back](/learn/tokens-that-can-be-taken-back/).
- **An order is read by its owner or by staff.**
  [Anyone else gets the same `404`](https://github.com/WildanFrananda/kinetix-order-service/blob/47f3a62482646bb5e43957fd44000eed39f608ed/Controllers/OrderController.cs#L143-L153)
  as for an order that does not exist, so the answer does not reveal that it does.
- **Staff** — the `operator` and `admin` roles — also read the sagas and the returns that need attention.
- **An admin** may
  [complete a delivered order early](https://github.com/WildanFrananda/kinetix-order-service/blob/47f3a62482646bb5e43957fd44000eed39f608ed/Controllers/OrderCompletionController.cs#L11-L16),
  under the same rules except the window, and may
  [reject a return whose goods never came back](https://github.com/WildanFrananda/kinetix-order-service/blob/47f3a62482646bb5e43957fd44000eed39f608ed/Application/Returns/ReturnRejection.cs#L17-L45),
  with a reason. A return does not lapse on a timer: the merchant both opens it and records the goods
  coming back, so a timer would pay a merchant for never recording them. A return whose goods came back
  cannot be rejected — the buyer is owed.
- **Warehouse's report that a parcel is packed** is accepted only for a paid order of the same
  merchant; an order that was cancelled or refunded is not revived and no courier is sent.
- **Other services** reach the gRPC port only with a certificate from Kinetix's CA naming a service on
  order's allow list, and order checks the identity of every server it calls in return; see
  [Who is calling?](/learn/who-is-calling/).

## Running in the background

| Worker | Does |
| --- | --- |
| `StuckSagaSweeper` | [unwinds checkouts that stopped part-way](https://github.com/WildanFrananda/kinetix-order-service/blob/47f3a62482646bb5e43957fd44000eed39f608ed/Infrastructure/Background/StuckSagaSweeper.cs#L45-L82) — it releases what was held and never pushes a checkout forward — in bounded rounds; see [The checkout saga](/learn/checkout-saga/) |
| `OrderCompletionSweeper` | every minute, [retries the refunds owed for returns, completes the orders whose window has closed, and retries the escrow releases owed to merchants](https://github.com/WildanFrananda/kinetix-order-service/blob/47f3a62482646bb5e43957fd44000eed39f608ed/Infrastructure/Background/OrderCompletionSweeper.cs#L48-L52), twenty at a time |
| `ShippingSettlementSweeper` | every minute, [settles the shipping fees owed to couriers](https://github.com/WildanFrananda/kinetix-order-service/blob/47f3a62482646bb5e43957fd44000eed39f608ed/Infrastructure/Background/ShippingSettlementSweeper.cs#L12-L16) that payment has not yet confirmed, twenty at a time, backing off to an hour |

## Operating it

- `/health` answers when the process is up; `/health/ready`
  [runs a real query](https://github.com/WildanFrananda/kinetix-order-service/blob/47f3a62482646bb5e43957fd44000eed39f608ed/Controllers/HealthController.cs#L19-L30)
  and turns `503` while the instance drains after `SIGTERM`, so traffic stops before the process does.
- `/metrics` serves Prometheus text with the names the platform contract gives order.
- Every outbound gRPC call
  [has a deadline](https://github.com/WildanFrananda/kinetix-order-service/blob/47f3a62482646bb5e43957fd44000eed39f608ed/Program.cs#L110-L114),
  five seconds unless `KINETIX_GRPC_DEADLINE_SECONDS` says otherwise, so a dependency that hangs becomes
  an answer instead of a stuck request.
