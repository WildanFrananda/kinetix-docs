Everything a browser, an integration or the courier app asks of Kinetix arrives at one place: Kong, running
without a database, with its whole configuration written in
[Pkl](https://github.com/WildanFrananda/kinetix-api-gateway/blob/ddea9d964f47bf42cd2bbbc5bf05ba47f0dc0349/config/gateway.pkl)
and rendered to Kong's declarative format. This page is checked against the gateway
[v1.8.0](https://github.com/WildanFrananda/kinetix-api-gateway/tree/ddea9d964f47bf42cd2bbbc5bf05ba47f0dc0349),
the version in production, on
[Kong 3.9.4](https://github.com/Kong/kong/tree/ddc85be461165c9eb4506669343aa0d0c627e687), the version the
image's [pinned digest](https://github.com/WildanFrananda/kinetix-api-gateway/blob/ddea9d964f47bf42cd2bbbc5bf05ba47f0dc0349/Dockerfile#L61-L64)
carries. What a client sends and gets back is in the [REST reference](/apis/rest/); this page is about why
the gateway is built the way it is.

## Hosts

Kong answers three public hosts and the backoffice's two unpublished addresses, and each serves something
different:

- **`api.wildanfrananda.my.id`** serves the API: every route under `/api/v1/`, identity's signing keys, matching's
  two WebSockets, and two answers Kong gives itself.
- **`storage.wildanfrananda.my.id`** holds uploaded files. Every path on it goes to the object store,
  [with the `Host` header kept and 16 MB a request](https://github.com/WildanFrananda/kinetix-api-gateway/blob/ddea9d964f47bf42cd2bbbc5bf05ba47f0dc0349/config/gateway.pkl#L507-L529):
  an upload's URL is signed over the host the phone sends, so a rewritten host would fail every signature.
- **`seller.wildanfrananda.my.id`** is the seller web app's host. On it Kong sends
  [`/bff/` and everything under it to the edge](https://github.com/WildanFrananda/kinetix-api-gateway/blob/ddea9d964f47bf42cd2bbbc5bf05ba47f0dc0349/config/gateway.pkl#L243-L249),
  path and `Host` unchanged, so that the [edge](/services/edge/) can tell the apps apart by host.
  [Every other path on it](https://github.com/WildanFrananda/kinetix-api-gateway/blob/ddea9d964f47bf42cd2bbbc5bf05ba47f0dc0349/config/gateway.pkl#L251-L257)
  is answered by Kong with
  [`404 Not found`](https://github.com/WildanFrananda/kinetix-api-gateway/blob/ddea9d964f47bf42cd2bbbc5bf05ba47f0dc0349/config/gateway.pkl#L171-L177),
  `/api/v1/` included.
- **The backoffice** has no public host. Staff reach it at two addresses that are not published: a Tor onion
  service, which comes into Kong on [a listener of its own](#tls-outside-and-two-listeners-inside), and an address
  on Kinetix's staff network behind [the staff gate](#the-staff-gate). At both, Kong sends
  [`/bff/` to the edge](https://github.com/WildanFrananda/kinetix-api-gateway/blob/ddea9d964f47bf42cd2bbbc5bf05ba47f0dc0349/config/gateway.pkl#L227-L241) with `Host` unchanged, and
  [every other path to the backoffice's static app](https://github.com/WildanFrananda/kinetix-api-gateway/blob/ddea9d964f47bf42cd2bbbc5bf05ba47f0dc0349/config/gateway.pkl#L261-L279).

The last rule for the seller web matters more than it looks. The API's routes name no host, so without it they
would answer on the seller web's host too, and an API answer served under a web app's origin is content on the
origin that holds that app's session cookie. On the backoffice's addresses the app's own route takes every path
outside `/bff/` for the same reason. A web app reaches the API only through `/bff/`, where the edge decides what
to forward. The [REST reference](/apis/rest/#address-and-transport) gives every host with an example request.

## TLS outside, and two listeners inside

The gateway has
[three listeners](https://github.com/WildanFrananda/kinetix-api-gateway/blob/ddea9d964f47bf42cd2bbbc5bf05ba47f0dc0349/Dockerfile#L87-L91),
and only the one that speaks TLS faces the internet. Nothing answers plain HTTP from outside: a port that
still answers in plaintext is a port clients keep using, and every token the gateway checks would cross the
network in clear on its way to being checked. The container
[refuses to start without a certificate](https://github.com/WildanFrananda/kinetix-api-gateway/blob/ddea9d964f47bf42cd2bbbc5bf05ba47f0dc0349/bin/entrypoint.sh#L150-L154).
So a client always speaks `https://`, and a WebSocket from a client is always `wss://`.

The second listener exists only inside Kinetix's network, and only the edge uses it: when a web app's call
under `/bff/api/` has to reach a service, or the seller web opens its socket, the edge sends it there. Every API
route is written once and
[rendered twice](https://github.com/WildanFrananda/kinetix-api-gateway/blob/ddea9d964f47bf42cd2bbbc5bf05ba47f0dc0349/config/gateway.pkl#L130-L160):
the route the TLS listener serves, and a twin with the same paths, methods, service, path rewrite and token
check, which the internal listener serves.
[A guard on every twin](https://github.com/WildanFrananda/kinetix-api-gateway/blob/ddea9d964f47bf42cd2bbbc5bf05ba47f0dc0349/config/gateway.pkl#L112-L119)
refuses a request that did not arrive in plain HTTP on that listener, reading the connection rather than a
header, so a request from outside that names a twin's host is refused before anything else runs.

A twin carries neither the staff gate nor the rate limit. Its peer is always the edge, so both would see the
edge's address in place of the browser's: the gate would refuse every admin, and every web user would share
one budget. The browser's own address is checked where the browser enters, on `/bff/`. `/health`,
`security.txt`, the courier's socket, the storage host and `/bff/` itself have no twin; matching's merchant
socket has one, for the edge, as [WebSockets](#websockets) explains. Behind both listeners, inside
the private network, Kong reaches each service over plain HTTP. Calls between services take a different path
altogether: gRPC over mutual TLS, described in [Who is calling?](/learn/who-is-calling/).

The third listener exists for the backoffice's onion service alone. Tor carries the browser's connection,
encrypted and authenticated end to end, to a Tor process inside Kinetix's network, which hands it to this listener
in plain HTTP; nothing outside that network reaches the port. Only the backoffice's two onion routes answer there,
each behind [a guard of the same kind](https://github.com/WildanFrananda/kinetix-api-gateway/blob/ddea9d964f47bf42cd2bbbc5bf05ba47f0dc0349/config/gateway.pkl#L121-L128), and the onion address named on the TLS
listener gets `421`. Those routes carry the rate limit but not the staff gate: their peer is always the Tor
process, and Tor's client authorization has already decided who may connect.

## WebSockets

Two sockets, both served by matching:
[`/ws/v1/matching/driver` and `/ws/v1/matching/merchant`](https://github.com/WildanFrananda/kinetix-api-gateway/blob/ddea9d964f47bf42cd2bbbc5bf05ba47f0dc0349/config/gateway.pkl#L475-L505),
each also with `/websocket` after it, the form Phoenix's JavaScript client dials. A WebSocket starts as an
ordinary HTTP request asking to upgrade, so Kong routes it like any other request and then passes the
upgraded connection through. The access token travels with the connection request, and matching checks it
before the socket opens —
[a courier's or an admin's for the driver socket](https://github.com/WildanFrananda/kinetix-matching-service/blob/7ef67a0ca1d0e8945f638de8a2f9684e84d06886/lib/fleet_pulse_web/channels/driver_socket.ex#L27-L49),
[a seller's or an admin's for the merchant socket](https://github.com/WildanFrananda/kinetix-matching-service/blob/7ef67a0ca1d0e8945f638de8a2f9684e84d06886/lib/fleet_pulse_web/channels/merchant_socket.ex#L24-L45).
A request with no token, or a bad one, is refused with `403`, one that matching cannot check because identity
is unreachable with `503`, and no socket is opened. The courier app's socket is described step by step in
[Go on duty and deliver](/apis/rest/courier-app/deliver/).

### The merchant socket's twin

The seller web holds no token, so it cannot open the merchant socket on the API host the way the courier app
opens its own. It asks the edge instead, on its own host, and the edge opens the socket to matching for it with
the session's access token, as the [edge](/services/edge/#the-seller-webs-merchant-socket) describes. That
connection goes through the internal listener, so the merchant socket's route is
[written like an API route](https://github.com/WildanFrananda/kinetix-api-gateway/blob/ddea9d964f47bf42cd2bbbc5bf05ba47f0dc0349/config/gateway.pkl#L490-L505)
and rendered with a twin: the same two paths and the same service, the guard first, and no staff gate, rate
limit or token check at Kong, because matching checks the token and the role itself. Kong passes an
upgrade through a plain-HTTP route as it does through a TLS one, so
[the twin needs nothing the API's twins lack](https://github.com/WildanFrananda/kinetix-api-gateway/blob/ddea9d964f47bf42cd2bbbc5bf05ba47f0dc0349/CLAUDE.md#L249-L256).

The twin stays inside the way every twin does.
[It names only the gateway's internal host, over plain HTTP](https://github.com/WildanFrananda/kinetix-api-gateway/blob/ddea9d964f47bf42cd2bbbc5bf05ba47f0dc0349/config/gateway.pkl#L141-L156),
and its guard refuses with `421` anything that did not arrive in plain HTTP on the internal listener, which
nothing outside Kinetix's network can reach. A plain-HTTP request for the same path that names any other host
matches no twin and gets Kong's `426`. The courier's socket has no twin at all: the courier app dials the TLS
listener.

### Ninety seconds for a quiet socket

Phoenix
[closes a socket that has received nothing for 60 seconds](https://github.com/phoenixframework/phoenix/blob/b5026660dc744424545e7d2e3b7547507443ab40/lib/phoenix/endpoint.ex#L1044-L1045),
and its JavaScript client
[sends a heartbeat every 30](https://github.com/phoenixframework/phoenix/blob/b5026660dc744424545e7d2e3b7547507443ab40/assets/js/phoenix/socket.js#L174).
The edge waits
[90 seconds](https://github.com/WildanFrananda/kinetix-edge-service/blob/eb13db007a21ca985ca33eca49e44dacf43e6354/nginx/nginx.conf#L102-L105)
on a quiet merchant socket, so that the proxy is never what ends a socket Phoenix still holds. Kong, by default,
[gives up after 60 seconds](https://github.com/Kong/kong/blob/ddc85be461165c9eb4506669343aa0d0c627e687/kong/db/schema/entities/services.lua#L40-L42)
without reading from or writing to a service, and the seller web's socket passes Kong twice: on `/bff/`, between
the browser and the edge, and on the twin, between the edge and matching. Left at the default, Kong would close a
quiet socket before either end meant to. So both of Kong's services on that path, the edge's, which takes
`/bff/` on both web apps' hosts, and the merchant socket's, which takes its public route and its twin, read
and write for 90 seconds
([the edge's](https://github.com/WildanFrananda/kinetix-api-gateway/blob/ddea9d964f47bf42cd2bbbc5bf05ba47f0dc0349/config/gateway.pkl#L221-L225),
[the socket's](https://github.com/WildanFrananda/kinetix-api-gateway/blob/ddea9d964f47bf42cd2bbbc5bf05ba47f0dc0349/config/gateway.pkl#L490-L494)).
Connecting still times out at Kong's default, and every other service keeps Kong's defaults. The price is paid
where something stalls: a `/bff/` call or a merchant socket, the public route included, that hears nothing now
waits 90 seconds for Kong's `504` or close instead of 60.

## A first lock on tokens

On five groups of routes — identity's signed-in routes, matching's REST API, payment, notary and
notification's handset registration — Kong
[checks the access token before the request moves on](https://github.com/WildanFrananda/kinetix-api-gateway/blob/ddea9d964f47bf42cd2bbbc5bf05ba47f0dc0349/config/gateway.pkl#L61-L70).
It knows
[one signer: identity, by its issuer, with identity's public key and RS256](https://github.com/WildanFrananda/kinetix-api-gateway/blob/ddea9d964f47bf42cd2bbbc5bf05ba47f0dc0349/config/gateway.pkl#L650-L662),
and it checks the signature and that the token has not expired. A token from anyone else, unsigned, or
signed with another algorithm is refused at the door with `401`.

Kong reads the token from `Authorization` and nowhere else. Its `jwt` plugin
[looks for a token in the query string, in cookies and in headers](https://github.com/Kong/kong/blob/ddc85be461165c9eb4506669343aa0d0c627e687/kong/plugins/jwt/handler.lua#L22-L80),
and
[its default reads a query parameter named `jwt`](https://github.com/Kong/kong/blob/ddc85be461165c9eb4506669343aa0d0c627e687/kong/plugins/jwt/schema.lua#L12-L23).
A token in a URL ends up in access logs, in browser history and in the `Referer` of the next page, so
[Kinetix names no query parameter and no cookie](https://github.com/WildanFrananda/kinetix-api-gateway/blob/ddea9d964f47bf42cd2bbbc5bf05ba47f0dc0349/config/gateway.pkl#L66-L67).
A token sent anywhere but `Authorization: Bearer …` is a missing token, and the request gets
[`401` with `{"message":"Unauthorized"}`](https://github.com/Kong/kong/blob/ddc85be461165c9eb4506669343aa0d0c627e687/kong/plugins/jwt/handler.lua#L160-L166)
before it leaves the gateway. The sockets carry no Kong token check: matching reads their token itself.

That is a first lock, not the only one. Kong does not ask whether the token is an access token or a
refresh token, or which audience it was issued for; the service behind it does, against identity's
published keys, and decides what the caller may do. Routes without Kong's check — sign-in and
registration, identity's signing keys, product search, the catalogue, cart and orders, reviews,
warehouse and pricing — are either public by design or checked by the service alone; each
[service page](/services/order/) says which. `/bff/` carries no token at all: the browser sends a cookie, and
the edge holds the tokens.

## The staff gate

The routes only an admin may call answer only Kinetix's staff network. Each has a route of its own carrying
Kong's
[`ip-restriction`](https://github.com/WildanFrananda/kinetix-api-gateway/blob/ddea9d964f47bf42cd2bbbc5bf05ba47f0dc0349/config/gateway.pkl#L72-L79),
which admits only the address ranges the environment names when the container starts:

- identity's lists of seller and courier applications and their counts, and approving or rejecting one
  ([gateway.pkl](https://github.com/WildanFrananda/kinetix-api-gateway/blob/ddea9d964f47bf42cd2bbbc5bf05ba47f0dc0349/config/gateway.pkl#L315-L328));
- catalog's category writes; reading the categories stays public
  ([gateway.pkl](https://github.com/WildanFrananda/kinetix-api-gateway/blob/ddea9d964f47bf42cd2bbbc5bf05ba47f0dc0349/config/gateway.pkl#L369-L375));
- warehouse's bins, stock receipts and stock adjustments
  ([gateway.pkl](https://github.com/WildanFrananda/kinetix-api-gateway/blob/ddea9d964f47bf42cd2bbbc5bf05ba47f0dc0349/config/gateway.pkl#L391-L428));
- matching's drivers and its backoffice API
  ([gateway.pkl](https://github.com/WildanFrananda/kinetix-api-gateway/blob/ddea9d964f47bf42cd2bbbc5bf05ba47f0dc0349/config/gateway.pkl#L443-L473));
- order's sagas, the returns that need attention, rejecting a return and completing an order
  ([gateway.pkl](https://github.com/WildanFrananda/kinetix-api-gateway/blob/ddea9d964f47bf42cd2bbbc5bf05ba47f0dc0349/config/gateway.pkl#L556-L567));
- and the whole backoffice at its staff-network address: the app and every call under `/bff/`, sign-in included
  ([gateway.pkl](https://github.com/WildanFrananda/kinetix-api-gateway/blob/ddea9d964f47bf42cd2bbbc5bf05ba47f0dc0349/config/gateway.pkl#L227-L234), [L265-L271](https://github.com/WildanFrananda/kinetix-api-gateway/blob/ddea9d964f47bf42cd2bbbc5bf05ba47f0dc0349/config/gateway.pkl#L265-L271)).
  Its onion service has no staff gate: there, Tor's client authorization decides who connects.

The gate reads
[the address of the connection](https://github.com/Kong/kong/blob/ddc85be461165c9eb4506669343aa0d0c627e687/kong/plugins/ip-restriction/handler.lua#L67-L92),
not a header a client could write, and anyone else gets `403` with a fixed message that does not repeat the
caller's address. On identity's and matching's admin routes
[Kong's token check runs first](https://github.com/WildanFrananda/kinetix-api-gateway/blob/ddea9d964f47bf42cd2bbbc5bf05ba47f0dc0349/CLAUDE.md#L79-L84),
so a request with no valid token gets the `401` before the gate is asked.

The gate is a second lock behind the services' own role checks, not a replacement for them.
[An endpoint that a user or an admin may call](https://github.com/WildanFrananda/kinetix-api-gateway/blob/ddea9d964f47bf42cd2bbbc5bf05ba47f0dc0349/CLAUDE.md#L53-L56),
such as reading a seller's application, is not fenced: a network cannot tell the two callers apart, so the
service decides. The ranges themselves are configuration, not code;
[the container refuses to start without them](https://github.com/WildanFrananda/kinetix-api-gateway/blob/ddea9d964f47bf42cd2bbbc5bf05ba47f0dc0349/bin/entrypoint.sh#L31-L34),
and the Pkl
[refuses an empty list and a range that admits every address](https://github.com/WildanFrananda/kinetix-api-gateway/blob/ddea9d964f47bf42cd2bbbc5bf05ba47f0dc0349/config/gateway.pkl#L16-L18).

## Limits, labels and counts

Every request:

- is limited, on the routes the TLS listener serves, to
  [100 requests a minute from one client address](https://github.com/WildanFrananda/kinetix-api-gateway/blob/ddea9d964f47bf42cd2bbbc5bf05ba47f0dc0349/config/gateway.pkl#L81-L89)
  on each route, counted on the gateway itself. The limit is
  [added to every route on the TLS listener](https://github.com/WildanFrananda/kinetix-api-gateway/blob/ddea9d964f47bf42cd2bbbc5bf05ba47f0dc0349/config/gateway.pkl#L133-L139)
  rather than once for the whole gateway,
  [because Kong cannot leave a route out of a global plugin](https://github.com/WildanFrananda/kinetix-api-gateway/blob/ddea9d964f47bf42cd2bbbc5bf05ba47f0dc0349/CLAUDE.md#L187-L193)
  and the twins must carry none; Kong
  [keeps a route's count under that route](https://github.com/Kong/kong/blob/ddc85be461165c9eb4506669343aa0d0c627e687/kong/plugins/rate-limiting/policies/init.lua#L68-L73),
  so one address has a budget on each route. A route is one service's group of paths, and `/bff/` on a web
  app's host is one route: a browser's sign-in and all its calls through the edge share it. The payment
  provider's notifications have
  [a limit of their own, 600 a minute](https://github.com/WildanFrananda/kinetix-api-gateway/blob/ddea9d964f47bf42cd2bbbc5bf05ba47f0dc0349/config/gateway.pkl#L586-L602),
  so a burst of payments is not throttled by the limit meant for people. The [REST reference](/apis/rest/#limits)
  lists which paths count together;
- carries an [`X-Request-Id`](https://github.com/WildanFrananda/kinetix-api-gateway/blob/ddea9d964f47bf42cd2bbbc5bf05ba47f0dc0349/config/gateway.pkl#L665-L672):
  the client's if it sent one, a new UUID if not, echoed back in the response so a support request can
  name the exact call;
- is [counted for Prometheus](https://github.com/WildanFrananda/kinetix-api-gateway/blob/ddea9d964f47bf42cd2bbbc5bf05ba47f0dc0349/config/gateway.pkl#L673-L682)
  by status, latency and upstream health.

## Browsers

Kong adds its `cors` plugin to a route
[only when the environment names browser origins](https://github.com/WildanFrananda/kinetix-api-gateway/blob/ddea9d964f47bf42cd2bbbc5bf05ba47f0dc0349/config/gateway.pkl#L133-L139),
and never to `/bff/`
([gateway.pkl](https://github.com/WildanFrananda/kinetix-api-gateway/blob/ddea9d964f47bf42cd2bbbc5bf05ba47f0dc0349/config/gateway.pkl#L158-L160)).
Production names none, so in production Kong answers no CORS preflight and adds no `Access-Control-*` header.
A preflight to the API host goes to the service like any other request:
[Kong's token check skips `OPTIONS`](https://github.com/WildanFrananda/kinetix-api-gateway/blob/ddea9d964f47bf42cd2bbbc5bf05ba47f0dc0349/config/gateway.pkl#L61-L70).

The web apps need no CORS. A page calls `/bff/` on its own host, the same origin as the page, and the edge
calls the API for it with a token the page never sees; the [edge](/services/edge/) explains why. The courier
app is not a browser and sends no `Origin`. The [REST reference](/apis/rest/#browsers) says what this means for
a client. Where an environment does name origins, as a lab may, the plugin
[never allows credentials](https://github.com/WildanFrananda/kinetix-api-gateway/blob/ddea9d964f47bf42cd2bbbc5bf05ba47f0dc0349/config/gateway.pkl#L91-L110),
and a `*` beside a named origin
[does not even evaluate](https://github.com/WildanFrananda/kinetix-api-gateway/blob/ddea9d964f47bf42cd2bbbc5bf05ba47f0dc0349/config/gateway.pkl#L13-L14).

## One image for every environment

The image carries the Pkl, not a rendered configuration. When the container starts it
[renders the configuration](https://github.com/WildanFrananda/kinetix-api-gateway/blob/ddea9d964f47bf42cd2bbbc5bf05ba47f0dc0349/bin/entrypoint.sh#L17-L91)
from the environment's own values — identity's public key, the issuer to trust, the browser origins (which
may be none, but must be stated), the staff ranges and the hosts, the onion address among them — refuses to start
if any is missing, and checks that the result contains a key to verify tokens with, the staff gate, and a guard on
every twin and on both onion routes: a gateway with no verification key would route everything and authenticate
nothing. The digest CI scanned is therefore the digest that runs everywhere.

Every change is evaluated before it merges.
[CI renders the Pkl](https://github.com/WildanFrananda/kinetix-api-gateway/blob/ddea9d964f47bf42cd2bbbc5bf05ba47f0dc0349/.github/workflows/ci.yml#L46-L182)
with a throwaway key and proves that an empty origin list leaves CORS out and that `*` beside a named origin
