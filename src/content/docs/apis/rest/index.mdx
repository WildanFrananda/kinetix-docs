Clients reach Kinetix over HTTP through one gateway, Kong. This reference lists every endpoint behind it,
grouped by the application that calls it — the buyer app, the seller web app, the courier app and the
backoffice — and, inside each application, by feature, in the order the application makes the calls. Each
endpoint shows its request, its fields and every answer it can give, each answer linked to the lines that
produce it.

The two mobile apps, the buyer app and the courier app, call the API host directly and send a bearer token. The two
web apps, the seller web app and the backoffice, never hold a token: each calls its own host, where the edge keeps
the session behind a cookie and calls the API with the session's token. Their pages show every endpoint as the
browser sends it to [the edge](#the-edge).

The services talk to one another over gRPC, which has [its own reference](/apis/grpc/). This page covers
what every endpoint shares: the addresses, tokens, the edge, request ids, browsers, limits, and the answers that do
not belong to any single endpoint.

## Address and transport

Kinetix answers on four public hosts:

- `api.wildanfrananda.my.id` serves every API endpoint, under `/api/v1/`; identity's public keys, at
  `/.well-known/jwks.json`; Kong's own two endpoints, `/health` and `/.well-known/security.txt`; and matching's two
  WebSockets, `wss://api.wildanfrananda.my.id/ws/v1/matching/driver?vsn=2.0.0` and
  `wss://api.wildanfrananda.my.id/ws/v1/matching/merchant?vsn=2.0.0`. Each socket also answers with `/websocket`
  after its path, the form Phoenix's JavaScript client dials
  ([gateway.pkl](https://github.com/WildanFrananda/kinetix-api-gateway/blob/ddea9d964f47bf42cd2bbbc5bf05ba47f0dc0349/config/gateway.pkl#L475-L505)).
- `storage.wildanfrananda.my.id` holds uploaded files. A client sends a file there at a URL a service signed for it;
  the bucket in those URLs is written `example-bucket` in the examples
  ([gateway.pkl](https://github.com/WildanFrananda/kinetix-api-gateway/blob/ddea9d964f47bf42cd2bbbc5bf05ba47f0dc0349/config/gateway.pkl#L507-L529)).
- `seller.wildanfrananda.my.id` serves the seller web app's calls under `/bff/`, which Kong passes to the edge,
  and under `/bff/` also matching's merchant socket for its page ([Realtime](#realtime)). Any other path on this
  host, `/api/v1/` paths included, gets Kong's `404 Not found`
  ([gateway.pkl](https://github.com/WildanFrananda/kinetix-api-gateway/blob/ddea9d964f47bf42cd2bbbc5bf05ba47f0dc0349/config/gateway.pkl#L243-L257)).
- The backoffice has no public host. Staff open it at an address that is not published, written
  `<backoffice origin>` in this reference: a Tor onion service that connects only a browser holding a client key,
  or, when Tor is unavailable, an address on Kinetix's staff network. On either, Kong passes `/bff/` to the edge
  and every other path to the backoffice's own static app
  ([gateway.pkl](https://github.com/WildanFrananda/kinetix-api-gateway/blob/ddea9d964f47bf42cd2bbbc5bf05ba47f0dc0349/config/gateway.pkl#L221-L279)).

Every public host answers over HTTPS only, and the sockets over `wss://`. Nothing answers plain HTTP: port 80 is closed, so
a client that dials an `http://` address by mistake does not connect and sends nothing, a token included
([gateway.pkl](https://github.com/WildanFrananda/kinetix-api-gateway/blob/ddea9d964f47bf42cd2bbbc5bf05ba47f0dc0349/config/gateway.pkl#L133-L139)).
A request to the API host:

```http
POST /api/v1/auth/login HTTP/1.1
Host: api.wildanfrananda.my.id
Content-Type: application/json
```

A part of a path written in braces, such as `{orderId}` in `/api/v1/orders/{orderId}`, is a value the client
puts there. Query parameters are not written in the path: each endpoint lists them with its other fields, marked
`query`.

## Tokens

identity issues every token. Signing in, registering, or completing a two-factor challenge returns a pair:
an access token to send with each request, and a refresh token to exchange for a new pair when the access
token expires. Both are JWTs signed with RS256. The mobile apps send the access token in one header; the web apps
never see it, because the edge sends it for them:

```http
Authorization: Bearer <access token>
```

Kong reads a token from this header only. A token in a `jwt` query parameter or in a cookie is no token to Kong: on a
route where Kong checks tokens, such a request gets Kong's `401` and never reaches the service
([gateway.pkl](https://github.com/WildanFrananda/kinetix-api-gateway/blob/ddea9d964f47bf42cd2bbbc5bf05ba47f0dc0349/config/gateway.pkl#L61-L70)).

The token is checked in one of two places:

- **By Kong, then by the service.** On the routes of identity's accounts (`/api/v1/auth`, `/api/v1/users`,
  `/api/v1/sellers`, `/api/v1/couriers`), matching, payment, the notary's proofs and notification's devices,
  Kong checks the signature and the expiry before the request reaches the service. A token it refuses gets one
  of [Kong's answers](#kongs-answers). The service then checks the rest: the audience, the kind of token, the
  role and the owner.
- **By the service alone.** Kong passes requests to catalog, search, pricing, order, review and warehouse
  without looking at the token. Each of them verifies the token itself wherever one is needed, and serves its
  public endpoints without one.

Each endpoint's **Access** line says which of the two applies to it, and who may call it.

Three of identity's rules reach every application:

- **`X-Kinetix-Client`.** The calls that issue or renew tokens — sign-in, registration, courier registration,
  two-factor verification and refresh — take an optional header that names the app. identity knows `courier-app`,
  and `seller-web` and `backoffice`, which the edge sends for the web apps. A request without the header is accepted,
  and production asks no proof that a named app is genuine; a name identity does not know is refused with `400`
  `UNKNOWN_CLIENT`. Tokens issued to a named app are renewed only by a request that names the same app; otherwise
  the refresh answers `401` `CLIENT_MISMATCH`
  ([client_gate.service.ts](https://github.com/WildanFrananda/kinetix-identity-service/blob/4193caf69b2ebea67534e619ebf3a2ccc384e857/src/application/services/client_gate.service.ts#L60-L105)).
  An app without a registered name, such as a buyer app, leaves the header out.
- **Two-factor authentication for every `admin`.** An admin account without it gets no token pair at sign-in, but an
  `enrolmentToken` that lasts ten minutes and reaches only the endpoints that set up and enable two-factor
  authentication; identity answers it `403` `TWO_FACTOR_ENROLMENT_ONLY` on its other endpoints
  ([identity's answers](#identity)). Once two-factor authentication is on, the admin signs in again, with the
  password and then a code. A refresh for an admin who no longer has it ends the session with `401`
  `TWO_FACTOR_REQUIRED`
  ([auth_usecase.service.ts](https://github.com/WildanFrananda/kinetix-identity-service/blob/4193caf69b2ebea67534e619ebf3a2ccc384e857/src/application/services/auth_usecase.service.ts#L63-L65),
  [L171-L179](https://github.com/WildanFrananda/kinetix-identity-service/blob/4193caf69b2ebea67534e619ebf3a2ccc384e857/src/application/services/auth_usecase.service.ts#L171-L179)).
  On the backoffice, the edge runs the enrolment.
- **`SIGN_IN_DELAYED`.** identity counts every check of an account's password or two-factor code, right or wrong,
  from any address. The first five pass at once; after that, each must come 1, 2, 4, 8, 16, 32 and at most 60
  seconds after the one before. A request inside that wait is refused with `429`, the code `SIGN_IN_DELAYED` and
  `Retry-After`, and nothing is checked. Waiting is enough: the account is never locked, a completed sign-in clears
  the count, and the count is forgotten an hour after the last check
  ([sign_in_attempt_policy.ts](https://github.com/WildanFrananda/kinetix-identity-service/blob/4193caf69b2ebea67534e619ebf3a2ccc384e857/src/domain/sign_in_attempt_policy.ts#L3-L35)).
  A code sent on a challenge identity has already ended is not counted: it gets that challenge's `401`, inside the
  wait too
  ([auth_usecase.service.ts](https://github.com/WildanFrananda/kinetix-identity-service/blob/4193caf69b2ebea67534e619ebf3a2ccc384e857/src/application/services/auth_usecase.service.ts#L86-L111)).
  The edge passes the same code to the web apps.

The sign-in pages show these calls in order: [buyer app](/apis/rest/buyer-app/sign-up-and-sign-in/),
[courier app](/apis/rest/courier-app/sign-in/), [seller web](/apis/rest/seller-web/sign-in/) and
[backoffice](/apis/rest/backoffice/sign-in/).

The public keys that verify every token are published by identity. No application needs them; a service or a

## The edge

The seller web app and the backoffice run in a browser, and a browser is never given a token. Each web app calls
only its own host, under `/bff/`, where Kong passes the call to the edge, `kinetix-edge-service`
([the service](/services/edge/)). The edge signs the browser in with identity, or on the seller web signs a new
account up, keeps the token pair in its session store, and gives the browser a cookie that names the session; on each
call it sends the API the session's access token. No token reaches the page, so a script in the page cannot read one.

### Sessions

The cookie is `__Host-kx_session`, a random value of 43 characters, set with
`Path=/; Secure; HttpOnly; SameSite=Strict`
([cookies.tl](https://github.com/WildanFrananda/kinetix-edge-service/blob/eb13db007a21ca985ca33eca49e44dacf43e6354/src/http/cookies.tl#L6-L17)).
The `__Host-` prefix makes the browser keep it for the exact host that set it and no other; `HttpOnly` hides it from
scripts; `SameSite=Strict` keeps the browser from sending it with a request that another site starts. A sign-in that
still waits for a two-factor code, or an admin's enrolment, is held behind a second cookie, `__Host-kx_pending`, with
the same attributes, for 300 or 600 seconds.

Each app admits its own roles and ends its sessions on its own clock
([apps.tl](https://github.com/WildanFrananda/kinetix-edge-service/blob/eb13db007a21ca985ca33eca49e44dacf43e6354/config/apps.tl#L16-L54),
[lifetimes.tl](https://github.com/WildanFrananda/kinetix-edge-service/blob/eb13db007a21ca985ca33eca49e44dacf43e6354/config/lifetimes.tl#L4-L7)):

| App | Roles | Idle limit | Absolute limit | Cookie |
| --- | --- | --- | --- | --- |
| backoffice | `admin` | 15 minutes | 8 hours | no `Max-Age`: it ends when the browser closes |
| seller web | `seller`, `customer` | 7 days | 30 days | `Max-Age` of 30 days |

Only the seller web offers sign-up, `POST /bff/register`, and the merchant socket, to a `seller`; on the backoffice
both answer `404`
([apps.tl](https://github.com/WildanFrananda/kinetix-edge-service/blob/eb13db007a21ca985ca33eca49e44dacf43e6354/config/apps.tl#L29-L30),
[L46-L47](https://github.com/WildanFrananda/kinetix-edge-service/blob/eb13db007a21ca985ca33eca49e44dacf43e6354/config/apps.tl#L46-L47),
[router.tl](https://github.com/WildanFrananda/kinetix-edge-service/blob/eb13db007a21ca985ca33eca49e44dacf43e6354/src/http/router.tl#L223-L227)).

The idle limit runs from the last call under `/bff/api/` or the last opening of the merchant socket; reading
`GET /bff/session` does not count
([session_use.tl](https://github.com/WildanFrananda/kinetix-edge-service/blob/eb13db007a21ca985ca33eca49e44dacf43e6354/src/http/session_use.tl#L37-L46)).
The role is checked at sign-in and sign-up, and again whenever the edge renews the tokens: an account whose role the
app does not admit gets no session, or loses the one it had, with `403` `ROLE_REFUSED`
([sign_in.tl](https://github.com/WildanFrananda/kinetix-edge-service/blob/eb13db007a21ca985ca33eca49e44dacf43e6354/src/http/sign_in.tl#L99-L110),
[sessions.tl](https://github.com/WildanFrananda/kinetix-edge-service/blob/eb13db007a21ca985ca33eca49e44dacf43e6354/src/http/sessions.tl#L418-L425)).
At the backoffice's staff-network address, every call under `/bff/` from outside that network, sign-in included,
gets Kong's `403`; the onion service needs no such gate, because Tor connects only a browser holding a client key
([gateway.pkl](https://github.com/WildanFrananda/kinetix-api-gateway/blob/ddea9d964f47bf42cd2bbbc5bf05ba47f0dc0349/config/gateway.pkl#L227-L234)).

The edge renews the token pair by itself. When a call under `/bff/api/`, or the opening of the merchant socket, finds
the access token less than 60 seconds from expiry, the edge exchanges the refresh token at identity before it goes
on, once per session even when several calls arrive together
([timing.tl](https://github.com/WildanFrananda/kinetix-edge-service/blob/eb13db007a21ca985ca33eca49e44dacf43e6354/config/timing.tl#L4-L6),
[session_use.tl](https://github.com/WildanFrananda/kinetix-edge-service/blob/eb13db007a21ca985ca33eca49e44dacf43e6354/src/http/session_use.tl#L48-L69),
[sessions.tl](https://github.com/WildanFrananda/kinetix-edge-service/blob/eb13db007a21ca985ca33eca49e44dacf43e6354/src/http/sessions.tl#L492-L513)).
A page never refreshes, and cannot. If identity refuses the renewal, the session ends with `401` `SESSION_ENDED`; if
identity cannot renew it now, the session is kept and the call gets `503` `IDENTITY_UNAVAILABLE`. A role granted
after the session started, such as a customer approved as a seller, reaches the session at the first renewal after
it.

### What a page sends

- **The cookie**, which the browser adds by itself to every request to the page's own host; `fetch` does so by
  default.
- **`Origin`** on `POST`, `PUT`, `PATCH` and `DELETE`, equal to the app's own origin, `https://` and its host;
  without `Origin`, `Sec-Fetch-Site: same-origin` passes as well. A browser sends them by itself on a `fetch` from
  the app's own page. Any other request that changes something is refused with `403` `CSRF_REFUSED` before the
  session is read
  ([csrf.tl](https://github.com/WildanFrananda/kinetix-edge-service/blob/eb13db007a21ca985ca33eca49e44dacf43e6354/src/http/csrf.tl#L12-L30)).
  The merchant socket's handshake is a `GET` and is checked more strictly: it must carry `Origin`, and exactly the
  seller web's
  ([merchant_socket.tl](https://github.com/WildanFrananda/kinetix-edge-service/blob/eb13db007a21ca985ca33eca49e44dacf43e6354/src/http/merchant_socket.tl#L53-L57)).
- **JSON bodies only**, sent with `Content-Type: application/json`; `fetch` sends a string body as `text/plain`
  unless told otherwise. A body of any other type, an HTML form or `multipart/form-data` included, is refused with
  `415` `JSON_REQUIRED`
  ([router.tl](https://github.com/WildanFrananda/kinetix-edge-service/blob/eb13db007a21ca985ca33eca49e44dacf43e6354/src/http/router.tl#L161-L185)),
  and a body over 1 MiB with `413`
  ([nginx.conf](https://github.com/WildanFrananda/kinetix-edge-service/blob/eb13db007a21ca985ca33eca49e44dacf43e6354/nginx/nginx.conf#L39-L40)).

### How a call reaches the API

`/bff/api/<path>` on an app's host is `/api/<path>` on the API, with the same method and query string
([api_path.tl](https://github.com/WildanFrananda/kinetix-edge-service/blob/eb13db007a21ca985ca33eca49e44dacf43e6354/src/http/api_path.tl#L7-L30)).
The edge takes `GET`, `HEAD`, `POST`, `PUT`, `PATCH` and `DELETE`
([forwarding.tl](https://github.com/WildanFrananda/kinetix-edge-service/blob/eb13db007a21ca985ca33eca49e44dacf43e6354/config/forwarding.tl#L9)).
This request from the seller web app reaches catalog as `POST /api/v1/products/create`, with
`Authorization: Bearer <access token>`:

```http
POST /bff/api/v1/products/create HTTP/1.1
Host: seller.wildanfrananda.my.id
Cookie: __Host-kx_session=<session>
Origin: https://seller.wildanfrananda.my.id
Content-Type: application/json
```

On the way, the edge rewrites the headers
([forwarding.tl](https://github.com/WildanFrananda/kinetix-edge-service/blob/eb13db007a21ca985ca33eca49e44dacf43e6354/config/forwarding.tl#L11-L38),
[forward_headers.tl](https://github.com/WildanFrananda/kinetix-edge-service/blob/eb13db007a21ca985ca33eca49e44dacf43e6354/src/http/forward_headers.tl#L27-L49)):

- From the page it passes on only `Accept`, `Accept-Language`, `Content-Type`, `Idempotency-Key`, `If-Match`,
  `If-None-Match` and `User-Agent`. Every other header stays at the edge: the cookie, an `Authorization` the page
  sets, and every `X-Kinetix-*` header among them.
- It adds `Authorization` with the session's access token, `X-Request-Id`, `X-Forwarded-For` with the browser's
  address, and, under `/api/v1/auth` and `/api/v1/couriers`, `X-Kinetix-Client` with the app's name, `seller-web` or
  `backoffice`
  ([forward.tl](https://github.com/WildanFrananda/kinetix-edge-service/blob/eb13db007a21ca985ca33eca49e44dacf43e6354/src/http/forward.tl#L36-L44)).
- The answer keeps the API's status, body and headers, except `Set-Cookie`, `Server`, `X-Powered-By`, the caching
  headers and those that describe the connection. Every answer from the edge carries `Cache-Control: no-store`, so
  no cache keeps it
  ([response_headers.tl](https://github.com/WildanFrananda/kinetix-edge-service/blob/eb13db007a21ca985ca33eca49e44dacf43e6354/src/http/response_headers.tl#L4-L6)).
- When a service is down behind Kong, the page gets Kong's own `502`, `503` or `504`, passed on like any answer. The
  edge answers `503` `API_UNAVAILABLE` itself only when it cannot reach the API, or identity for `/api/v1/auth` and
  `/api/v1/couriers`, or has no answer within 60 seconds
  ([forward.tl](https://github.com/WildanFrananda/kinetix-edge-service/blob/eb13db007a21ca985ca33eca49e44dacf43e6354/src/http/forward.tl#L61-L77)).

### Realtime

The seller web's page gets its realtime from matching's merchant socket, which the edge carries: the page opens it on
its own host, under `/bff/`, and [Pack orders](/apis/rest/seller-web/packing/) gives its address, its handshake answers
and its messages in the order the seller web uses them. The browser sends the session cookie with the handshake, and
the page sends no token. The edge checks the session as for a call under `/bff/api/`, admits only a `seller`, and
opens matching's socket with the session's access token; the `101` it passes back to the page carries neither the
token nor a cookie
([merchant_socket.tl](https://github.com/WildanFrananda/kinetix-edge-service/blob/eb13db007a21ca985ca33eca49e44dacf43e6354/src/http/merchant_socket.tl#L45-L103)).
The page and matching then exchange Phoenix frames through the edge. As for a call, an answer from behind the edge
comes back with its status, Kong's own included when matching is down; the edge answers `503` `API_UNAVAILABLE`
itself only when it cannot reach the API or has no handshake answer within 90 seconds
([nginx.conf](https://github.com/WildanFrananda/kinetix-edge-service/blob/eb13db007a21ca985ca33eca49e44dacf43e6354/nginx/nginx.conf#L102-L108)).
The backoffice has no socket.

### Calls the edge refuses

Six of identity's paths are refused with `404`, in any letter case and with everything below them:
`/bff/api/v1/auth/login`, `/register`, `/refresh`, `/logout`, `/2fa/verify` and `/bff/api/v1/couriers/register`
([forwarding.tl](https://github.com/WildanFrananda/kinetix-edge-service/blob/eb13db007a21ca985ca33eca49e44dacf43e6354/config/forwarding.tl#L40-L47)).
Their answers carry tokens, which a page must never hold. On the seller web a new account is created with
`POST /bff/register`, which starts its session at once; a web app signs in with `POST /bff/login` and, when a code is
needed, `POST /bff/2fa/verify`; an admin without two-factor authentication enrols with `POST /bff/2fa/setup` and
`POST /bff/2fa/enable`; `POST /bff/logout` signs out; the edge refreshes by itself. The seller web's
[sign-up](/apis/rest/seller-web/become-a-seller/) and [sign-in](/apis/rest/seller-web/sign-in/) and the
[backoffice's sign-in](/apis/rest/backoffice/sign-in/) show these calls in order. The backoffice offers no sign-up,
and no courier account can be registered through the edge.

The edge answers these itself, to calls under `/bff/`. Its own endpoints list their other answers on the sign-in
pages; an answer from the API passes through with its status and body unchanged.

## Request ids

Kong gives every request an `X-Request-Id` header: the client's own, when it sends one, or a new UUID. The
service receives it, and Kong returns it in the response
([gateway.pkl](https://github.com/WildanFrananda/kinetix-api-gateway/blob/ddea9d964f47bf42cd2bbbc5bf05ba47f0dc0349/config/gateway.pkl#L665-L672)).
Send your own id when you want to find a request in the logs later. Several services repeat it in their error
bodies, for example identity's `traceId`. matching repeats it as `traceId` too, the answers to its two sockets'
handshakes included, when the id has 20 to 200 characters; a shorter or longer one, which only a client can send, it
replaces with an id of its own
([request_trace.ex](https://github.com/WildanFrananda/kinetix-matching-service/blob/7ef67a0ca1d0e8945f638de8a2f9684e84d06886/lib/fleet_pulse_web/request_trace.ex#L1-L26),
[error_json.ex](https://github.com/WildanFrananda/kinetix-matching-service/blob/7ef67a0ca1d0e8945f638de8a2f9684e84d06886/lib/fleet_pulse_web/controllers/error_json.ex#L22-L29)).
Kong's own error bodies carry a different value, `request_id`, which
is Kong's internal id for the request; Kong also returns it in the `X-Kong-Request-Id` header
([Kong's defaults](https://github.com/Kong/kong/blob/ddc85be461165c9eb4506669343aa0d0c627e687/kong/templates/kong_defaults.lua#L71)).
The gateway's access log records both, and records the path without its query string
([access_log.conf](https://github.com/WildanFrananda/kinetix-api-gateway/blob/ddea9d964f47bf42cd2bbbc5bf05ba47f0dc0349/config/access_log.conf#L1-L8)).

Through the edge the same id travels on: the edge sends it to the API, the merchant socket's handshake included, and
repeats it as `requestId` in its own error bodies, provided it is 1 to 128 letters, digits or `.-_:#@`; otherwise the
edge uses an id of its own
([context.tl](https://github.com/WildanFrananda/kinetix-edge-service/blob/eb13db007a21ca985ca33eca49e44dacf43e6354/src/http/context.tl#L44-L51),
[request_id.tl](https://github.com/WildanFrananda/kinetix-edge-service/blob/eb13db007a21ca985ca33eca49e44dacf43e6354/src/http/request_id.tl#L4-L14)).

## Browsers

Kong trusts no browser origin. Production configures none, so Kong adds its `cors` plugin to no route and puts no
`Access-Control-*` header on an answer
([gateway.pkl](https://github.com/WildanFrananda/kinetix-api-gateway/blob/ddea9d964f47bf42cd2bbbc5bf05ba47f0dc0349/config/gateway.pkl#L133-L139)).
No service behind Kong adds `Access-Control-*` headers of its own either; review, whose framework would, turns that
off
([bootstrap/app.php](https://github.com/WildanFrananda/kinetix-review-service/blob/e3ca897c68947dd7ba4a47f04355e5e91da9afa8/bootstrap/app.php#L34)).
Kong checks no token on an `OPTIONS` request
([gateway.pkl](https://github.com/WildanFrananda/kinetix-api-gateway/blob/ddea9d964f47bf42cd2bbbc5bf05ba47f0dc0349/config/gateway.pkl#L61-L70),
[Kong's jwt plugin](https://github.com/Kong/kong/blob/ddc85be461165c9eb4506669343aa0d0c627e687/kong/plugins/jwt/handler.lua#L306-L310))
and otherwise treats it as any other request.

The web apps need no CORS. Each page calls `/bff/` on its own host, the same origin as the page, and the edge calls
the API for it ([The edge](#the-edge)); the edge answers an `OPTIONS` with `405`. The buyer app and the courier app
are not browsers: they send no `Origin`, and none of this applies to them.

## Limits

- **100 requests a minute** from one client address to each of Kong's routes
  ([gateway.pkl](https://github.com/WildanFrananda/kinetix-api-gateway/blob/ddea9d964f47bf42cd2bbbc5bf05ba47f0dc0349/config/gateway.pkl#L81-L89),
  [L112-L118](https://github.com/WildanFrananda/kinetix-api-gateway/blob/ddea9d964f47bf42cd2bbbc5bf05ba47f0dc0349/config/gateway.pkl#L133-L139)).
  A route holds one service's paths, sometimes several prefixes of it: `/api/v1/cart` and `/api/v1/orders` share one
  count, for example. Each admin-only route, `/health`, `/.well-known/security.txt`, each socket, the storage host
  and `/bff/` on each web app's host count on their own; on a web app, every call a browser makes under `/bff/`,
  sign-in and the merchant socket's handshakes included, shares that one count. The Midtrans notification route
  allows 600 a minute
  ([gateway.pkl](https://github.com/WildanFrananda/kinetix-api-gateway/blob/ddea9d964f47bf42cd2bbbc5bf05ba47f0dc0349/config/gateway.pkl#L586-L602)).
  Past the limit, Kong answers `429` with `Retry-After`.
- **Waits.** Kong waits 60 seconds for a service, and 90 seconds on `/bff/` of the two web apps' hosts and on
  matching's merchant socket; a service that takes longer leaves the client with Kong's `504`
  ([gateway.pkl](https://github.com/WildanFrananda/kinetix-api-gateway/blob/ddea9d964f47bf42cd2bbbc5bf05ba47f0dc0349/config/gateway.pkl#L29),
  [L191-L196](https://github.com/WildanFrananda/kinetix-api-gateway/blob/ddea9d964f47bf42cd2bbbc5bf05ba47f0dc0349/config/gateway.pkl#L221-L226),
  [L441-L446](https://github.com/WildanFrananda/kinetix-api-gateway/blob/ddea9d964f47bf42cd2bbbc5bf05ba47f0dc0349/config/gateway.pkl#L490-L495)).
  On `/bff/` the edge usually stops waiting first: a call under `/bff/api/` with no answer within 60 seconds, or one
  of the edge's own calls to identity with none within 5, gets the edge's `503`
  ([timing.tl](https://github.com/WildanFrananda/kinetix-edge-service/blob/eb13db007a21ca985ca33eca49e44dacf43e6354/config/timing.tl#L12-L17),
  [the edge's answers](#the-edges-answers)).
- **Body size.** Kong sets no limit of its own on the API host
  ([Kong's defaults](https://github.com/Kong/kong/blob/ddc85be461165c9eb4506669343aa0d0c627e687/kong/templates/kong_defaults.lua#L90));
  a service that limits bodies lists its own `413` among its answers. The storage host takes **16 MB** per upload
  ([gateway.pkl](https://github.com/WildanFrananda/kinetix-api-gateway/blob/ddea9d964f47bf42cd2bbbc5bf05ba47f0dc0349/config/gateway.pkl#L517-L524)),
  and the edge **1 MiB** per request.
- Some endpoints have a tighter limit of their own, set by their service, such as five sign-in attempts a
  minute from one address. It is listed on the endpoint. identity's delay per account is under [Tokens](#tokens).

## Kong's answers

Kong answers these itself, before or instead of a service. They can come from any endpoint, so the endpoints do
not repeat them. The `401`s come only from the routes where Kong checks the token; the `403` only from the
admin-only routes and from the backoffice's staff-network address; `404 Not found` only from the seller web's host;
and the `413` only from the storage host. Calls through the edge get them too, from the web app's host in front of
the edge and from the API behind it, whose answers the edge passes on.
