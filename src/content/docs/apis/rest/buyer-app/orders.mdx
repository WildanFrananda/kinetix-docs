order answers the orders whose buyer is the access token's `sub`. A buyer app lists them (step 1), opens
one (step 2), and tracks an active delivery live over WebSocket (step 3). The order that
[checkout](/apis/rest/buyer-app/checkout/) placed is read the same way.

## 1. List the orders

Newest first, and orders placed at the same instant by `id`, so every order has one place in the list
([OrderService.cs](https://github.com/WildanFrananda/kinetix-order-service/blob/a0167a3ec43e857e85401924b4bee486e596d4fd/Application/Services/OrderService.cs#L637-L642)).
`status` narrows the list to one status. The app asks for the next `page` while `page` × `pageSize` is below
`totalCount`, up to `page` 10,000, the last one order serves (`maxPage`). Pages are cut by position, so an
order placed while the app pages makes the next page repeat orders already shown: the app drops repeats by
`id`, and reads page 1 again to show orders placed since. Each item's `id` opens the order in step 2.

<RestEndpoint id="order.listMyOrders" />

## 2. Read one order

`{orderId}` is an item's `id` from step 1, or `id` from checkout's answer; the `orderNumber` is not accepted
here. The answer shows the order's `status`, its lines and its amounts, and `driverPrincipalId` once a
courier has delivered it. A delivered order can be [reviewed](/apis/rest/buyer-app/reviews/), and its
history [proven](/apis/rest/buyer-app/proofs/#5-fetch-an-orders-evidence).

## 3. Track courier location live

While an order is assigned or picked up, the buyer app opens the unified event socket at
`wss://api.wildanfrananda.my.id/ws/v1/events` with its Bearer access token
([event_socket.tl](https://github.com/WildanFrananda/kinetix-edge-service/blob/8c0fa9447c9d9fea964540ed1f8d032a3341b702/src/http/event_socket.tl#L601-L630)).
Unlike couriers and sellers, a buyer connects only to edge — no upstream socket is opened to matching
([#L331-L334](https://github.com/WildanFrananda/kinetix-edge-service/blob/8c0fa9447c9d9fea964540ed1f8d032a3341b702/src/http/event_socket.tl#L331-L334)).

<RestSocket id="edge.buyerSocket" />

Send `subscription.subscribe` with the order's `id` from step 1 or 2 (`orderId` UUID). Edge asks order
`GET /api/v1/orders/{orderId}` using the buyer's token to confirm ownership and resolve `orderNumber`, then
subscribes to matching's Redis Pub/Sub channel for that order number
([#L222-L305](https://github.com/WildanFrananda/kinetix-edge-service/blob/8c0fa9447c9d9fea964540ed1f8d032a3341b702/src/http/event_socket.tl#L222-L305)).
