A seller reads what its sales have earned from payment and what buyers think of its products from review. The
wallet is found by the session's access token, which must carry the role `seller`: a `customer` session gets
payment's `403`. The reviews are found by the seller's `principalId` from
[Sign in](/apis/rest/seller-web/sign-in/), step 3. Review reads no token for them, but through the edge every call
needs the session all the same.

## 1. Read the wallet

Payment holds the seller's share of each paid order and releases it when the order is completed; the answer shows
both amounts. The balance is all that payment's REST API shows a seller: no endpoint lists the payments behind it
([WalletController.java](https://github.com/WildanFrananda/kinetix-payment-service/blob/ae1f3e07d4849f51bbc41b8cb5dd356dcfa5d793/modules/api/src/main/java/com/kinetix/payment/api/controller/WalletController.java#L21-L84)).
