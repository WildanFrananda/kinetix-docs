A signed-in seller, or a customer applying to sell, turns on two-factor authentication for its own account in two
calls, a new secret (step 1) and a code that proves the authenticator app holds it (step 2), and can turn it off
later (step 3). The calls go through the edge to identity, which asks for the account's password on each: the edge
sends the session's access token, and an access token alone cannot change a second factor. `{id}` in every path is
the account id, `userId` from `GET /bff/api/v1/auth/me` ([Sign in](/apis/rest/seller-web/sign-in/), step 4). Once
the second factor is on, every sign-in on the seller web answers `mfaRequired` first, which the application answers
as in [step 2 of Sign in](/apis/rest/seller-web/sign-in/#2-answer-the-two-factor-challenge).

A `401` from identity on these calls is about the password, not about the session: the edge passes identity's
answer through as it is and leaves the session alone
([forward.tl](https://github.com/WildanFrananda/kinetix-edge-service/blob/0a52d5805b57a818b16b05848b8333d34115f682/src/http/forward.tl#L70-L77)),
so the application asks for the password again rather than for a new sign-in. A `429` `SIGN_IN_DELAYED` means
too many password or code checks of the account in a row: the application waits the seconds in `Retry-After`.

## 1. Get a new secret

The seller types the account's password, sent as `password`. The answer's `qrCodeUrl` is an `otpauth://` URI: the
application shows it as a QR code for the authenticator app to scan, and shows `twoFactorSecret` for a seller who
types it in instead. Nothing is in force yet. Asking again before step 2 replaces the secret, so the authenticator
must hold the latest one.

<RestEndpoint id="identity.setupTwoFactor" via="seller-web" />

## 2. Confirm with a code

The seller types the six digits the authenticator app shows now, sent as `code` with the password again. A `200`
with `enabled: true` puts the second factor in force for every later sign-in. This session stays: identity keeps
the session whose access token the edge sent, and ends every other session of the account, on other browsers and
devices
([auth_usecase.service.ts](https://github.com/WildanFrananda/kinetix-identity-service/blob/14a5d4291f2e4987e2ef774f68dc3888c509617c/src/application/services/auth_usecase.service.ts#L307-L312)).

<RestEndpoint id="identity.enableTwoFactor" via="seller-web" />

## 3. Turn it off

With the password and a current code from the same authenticator app. A `200` with `enabled: false` deletes the
secret, and later sign-ins answer a session at once. As in step 2, this session stays and every other session of
the account ends
([auth_usecase.service.ts](https://github.com/WildanFrananda/kinetix-identity-service/blob/14a5d4291f2e4987e2ef774f68dc3888c509617c/src/application/services/auth_usecase.service.ts#L337-L342)).
