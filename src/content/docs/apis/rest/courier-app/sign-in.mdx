A courier whose account an admin has approved signs in with an email and a password. identity answers a token
pair, or a challenge when the account has two-factor authentication on; the courier app then asks matching for
the courier's record, whose `id` the [driver socket](/apis/rest/courier-app/deliver/) needs. The calls, in
order: sign in, complete the second factor when identity asks for it, read the courier record. The account comes
from [registration](/apis/rest/courier-app/register/).

## 1. Sign in with email and password

The courier app sends the email without surrounding spaces and the password as typed
([login_view_model.dart](https://github.com/WildanFrananda/kinetix-courier-mobile/blob/29a96d33884f3ee9ff2831043e34aee2da235088/lib/viewmodels/login_view_model.dart#L33-L35),
[session_repository_impl.dart](https://github.com/WildanFrananda/kinetix-courier-mobile/blob/29a96d33884f3ee9ff2831043e34aee2da235088/lib/repositories/session_repository_impl.dart#L97-L155)).
On this call, as on the code step, registration and every refresh, it also sends two headers:
`X-Kinetix-Client: courier-app`, and `X-Firebase-AppCheck` with a Firebase App Check token from the phone
([driver_api.dart](https://github.com/WildanFrananda/kinetix-courier-mobile/blob/29a96d33884f3ee9ff2831043e34aee2da235088/lib/services/auth/driver_api.dart#L12-L38),
[client_proof.dart](https://github.com/WildanFrananda/kinetix-courier-mobile/blob/29a96d33884f3ee9ff2831043e34aee2da235088/lib/services/attestation/client_proof.dart#L14-L49)).
identity knows the name `courier-app` and binds the session's tokens to it. As production is configured, it
asks the courier app for no proof, so it does not read `X-Firebase-AppCheck`
([client_gate.service.ts](https://github.com/WildanFrananda/kinetix-identity-service/blob/4193caf69b2ebea67534e619ebf3a2ccc384e857/src/application/services/client_gate.service.ts#L60-L85)).

A `200` carrying `mfaRequired` goes to step 2 with its `challengeToken`; a `200` carrying the token pair goes
to step 3. For an approved courier, `user.role` is `courier`. A `200` carrying `mfaEnrolmentRequired` comes only
to an admin account: the courier app answers that it is for couriers, keeps nothing and asks matching nothing
([session_repository_impl.dart](https://github.com/WildanFrananda/kinetix-courier-mobile/blob/29a96d33884f3ee9ff2831043e34aee2da235088/lib/repositories/session_repository_impl.dart#L119-L123)).
On a `429`, the courier app takes the wait from `retryAfterSeconds`, or from `Retry-After`, counts it down on the
screen and sends nothing until it has passed
([identity_error.dart](https://github.com/WildanFrananda/kinetix-courier-mobile/blob/29a96d33884f3ee9ff2831043e34aee2da235088/lib/services/auth/identity_error.dart#L52-L74),
[sign_in_delay_mixin.dart](https://github.com/WildanFrananda/kinetix-courier-mobile/blob/29a96d33884f3ee9ff2831043e34aee2da235088/lib/mixins/sign_in_delay_mixin.dart#L7-L54),
[login_view_model.dart](https://github.com/WildanFrananda/kinetix-courier-mobile/blob/29a96d33884f3ee9ff2831043e34aee2da235088/lib/viewmodels/login_view_model.dart#L124-L133)).

## 2. Complete two-factor authentication

Only when step 1 answered `mfaRequired`. Send `challengeToken` from that answer and the six digits the courier's
authenticator app shows, within `expiresIn` seconds of step 1. The courier app notes that deadline when the
challenge arrives, and once it has passed asks the courier to sign in again instead of sending the code
([login_view_model.dart](https://github.com/WildanFrananda/kinetix-courier-mobile/blob/29a96d33884f3ee9ff2831043e34aee2da235088/lib/viewmodels/login_view_model.dart#L70-L83),
[#L114-L122](https://github.com/WildanFrananda/kinetix-courier-mobile/blob/29a96d33884f3ee9ff2831043e34aee2da235088/lib/viewmodels/login_view_model.dart#L114-L122)).
It sends the same two headers as in step 1, and waits out a `429` the same way, keeping the challenge. A `401`
with `WRONG_CODE` leaves the challenge open: the courier app shows the refusal and takes the next code. After
any other `401`, the challenge can never succeed: the courier app drops it and asks for the password again.
It tells `WRONG_CODE` apart by its `message`, `That code is not valid`
([session_repository_impl.dart](https://github.com/WildanFrananda/kinetix-courier-mobile/blob/29a96d33884f3ee9ff2831043e34aee2da235088/lib/repositories/session_repository_impl.dart#L394-L404),
[identity_error.dart](https://github.com/WildanFrananda/kinetix-courier-mobile/blob/29a96d33884f3ee9ff2831043e34aee2da235088/lib/services/auth/identity_error.dart#L76-L79),
[login_view_model.dart](https://github.com/WildanFrananda/kinetix-courier-mobile/blob/29a96d33884f3ee9ff2831043e34aee2da235088/lib/viewmodels/login_view_model.dart#L162-L169)).
The `200` carries the same token pair as a sign-in without a second factor; go on to step 3. The challenge is
spent by then, so a `200` the courier app cannot read sends the courier back to the password
([session_repository_impl.dart](https://github.com/WildanFrananda/kinetix-courier-mobile/blob/29a96d33884f3ee9ff2831043e34aee2da235088/lib/repositories/session_repository_impl.dart#L157-L195)).

## 3. Read the courier record

Send the access token from step 1 or step 2. `data.id` is the driver id: the courier's channel on the driver
socket is `driver:<data.id>`. A `403` with `pending_approval` means an admin has not approved the courier yet,
and a `404` means the account has filed no vehicle; [registration](/apis/rest/courier-app/register/) covers
both. The courier app decides what to keep from this answer
([session_repository_impl.dart](https://github.com/WildanFrananda/kinetix-courier-mobile/blob/29a96d33884f3ee9ff2831043e34aee2da235088/lib/repositories/session_repository_impl.dart#L316-L354)):

- on `200` it stores the token pair with `data.id`, then opens the socket;
- on `403` `pending_approval` it stores the pair without a driver id and shows the waiting screen; the next read
  of this record after approval fills the id in;
- on any other answer, or none, it sends the new pair to
  [sign-out](/apis/rest/courier-app/stay-signed-in/), waiting at most five seconds, and stores nothing, so no
  refresh token is left valid on the server and forgotten on the phone.
