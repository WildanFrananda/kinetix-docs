Catalog keeps the platform's product categories, and only an admin changes them: a seller files each product under a
category's `id`, and pricing's category discounts name a category's `slug`
([Platform promotions](/apis/rest/backoffice/platform-promotions/)). The admin, signed in as on
[Sign in](/apis/rest/backoffice/sign-in/), lists the categories, reads one, and creates, renames or deletes them. The
two reads are public; the three writes need the admin's access token, which catalog checks itself.

## 1. List the categories

Every category comes back in one answer, with no paging. Each one's `id` is the value the later steps take in the
path.

<RestEndpoint id="catalog.listCategories" />

## 2. Read one category

Read a category by the `id` from step 1, for example to show it before an edit.

<RestEndpoint id="catalog.getCategory" />

## 3. Create a category

Send a `name` and a `slug`; both must be unused by every other category. Keep the `id` of the answer: it is what sellers
send as `category_id` when they create a product.

<RestEndpoint id="catalog.createCategory" />

## 4. Rename a category

The update replaces both values, so send `name` and `slug` together, the unchanged one as it is, with `id` from step 1
or 3 in the path.

<RestEndpoint id="catalog.updateCategory" />

## 5. Delete a category

A category can be deleted only while no product is filed under it, withdrawn products included. A `409` gives the
count in `product_count`; those products' merchants have to move them to another category before the admin can delete
it.

<RestEndpoint id="catalog.deleteCategory" />
