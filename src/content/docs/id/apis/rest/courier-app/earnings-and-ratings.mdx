Dua pembacaan yang dilakukan client kurir tentang akun kurir itu sendiri: wallet driver di payment, tempat ongkos
kirim ditahan lalu dicairkan ke kurir, dan rating yang diberikan pembeli kepada kurir di review. Keduanya tidak
saling bergantung, dan keduanya dilakukan setelah [masuk](/id/apis/rest/courier-app/sign-in/). Aplikasi kurir di
commit `29a96d3` belum memanggil keduanya: satu-satunya request HTTP-nya ke Kinetix adalah panggilan ke identity
dan matching di API client-nya
([driver_api.dart](https://github.com/WildanFrananda/kinetix-courier-mobile/blob/29a96d33884f3ee9ff2831043e34aee2da235088/lib/services/auth/driver_api.dart#L8-L48))
dan upload foto di [Mulai bertugas dan mengantar](/id/apis/rest/courier-app/deliver/).

## 1. Baca wallet driver

Kirim access token yang role-nya `courier`. Token yang diterbitkan sebelum admin menyetujui kurir itu masih
menyebut `customer` dan mendapat `403`; [refresh](/id/apis/rest/courier-app/register/) sekali setelah disetujui.
Wallet-nya selalu milik pemanggil sendiri, jadi path-nya tidak menyebut siapa pun.

<RestEndpoint id="payment.driverBalance" />

## 2. Daftar rating kurir

Path-nya memakai principal id kurir: `user.principalId` di jawaban masuk, registrasi, atau refresh. Daftarnya
publik dan tidak butuh token. Minta halaman berikutnya dengan `page` selama nilainya masih di bawah `last_page`.
