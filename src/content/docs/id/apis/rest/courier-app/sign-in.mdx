Kurir yang akunnya sudah disetujui admin masuk dengan email dan password. identity menjawab sepasang token, atau
sebuah challenge bila akunnya mengaktifkan autentikasi dua faktor; aplikasi kurir lalu meminta data kurir ke
matching, yang `id`-nya dibutuhkan [driver socket](/id/apis/rest/courier-app/deliver/). Urutan panggilannya:
masuk, menyelesaikan faktor kedua bila identity memintanya, membaca data kurir. Akunnya berasal dari
[registrasi](/id/apis/rest/courier-app/register/).

## 1. Masuk dengan email dan password

Aplikasi kurir mengirim email tanpa spasi di awal dan akhir, dan password persis seperti diketik
([login_view_model.dart](https://github.com/WildanFrananda/kinetix-courier-mobile/blob/29a96d33884f3ee9ff2831043e34aee2da235088/lib/viewmodels/login_view_model.dart#L33-L35),
[session_repository_impl.dart](https://github.com/WildanFrananda/kinetix-courier-mobile/blob/29a96d33884f3ee9ff2831043e34aee2da235088/lib/repositories/session_repository_impl.dart#L97-L155)).
Pada panggilan ini, seperti pada langkah kode, registrasi, dan setiap refresh, aplikasi juga mengirim dua header:
`X-Kinetix-Client: courier-app`, dan `X-Firebase-AppCheck` berisi token Firebase App Check dari ponsel
([driver_api.dart](https://github.com/WildanFrananda/kinetix-courier-mobile/blob/29a96d33884f3ee9ff2831043e34aee2da235088/lib/services/auth/driver_api.dart#L12-L38),
[client_proof.dart](https://github.com/WildanFrananda/kinetix-courier-mobile/blob/29a96d33884f3ee9ff2831043e34aee2da235088/lib/services/attestation/client_proof.dart#L14-L49)).
identity mengenal nama `courier-app` dan mengikat token session itu ke nama tersebut. Sesuai konfigurasi
production, identity tidak meminta bukti apa pun dari aplikasi kurir, jadi `X-Firebase-AppCheck` tidak dibacanya
([client_gate.service.ts](https://github.com/WildanFrananda/kinetix-identity-service/blob/14a5d4291f2e4987e2ef774f68dc3888c509617c/src/application/services/client_gate.service.ts#L60-L85)).

Jawaban `200` yang membawa `mfaRequired` lanjut ke langkah 2 dengan `challengeToken`-nya; jawaban `200` yang
membawa pasangan token lanjut ke langkah 3. Untuk kurir yang sudah disetujui, `user.role` bernilai `courier`.
Jawaban `200` yang membawa `mfaEnrolmentRequired` hanya datang untuk akun admin: aplikasi kurir menjawab bahwa
aplikasinya untuk kurir, tidak menyimpan apa pun, dan tidak bertanya apa pun ke matching
([session_repository_impl.dart](https://github.com/WildanFrananda/kinetix-courier-mobile/blob/29a96d33884f3ee9ff2831043e34aee2da235088/lib/repositories/session_repository_impl.dart#L119-L123)).
Pada jawaban `429`, aplikasi kurir mengambil lama tunggu dari `retryAfterSeconds`, atau dari `Retry-After`,
menghitung mundur di layar, dan tidak mengirim apa pun sampai waktunya lewat
([identity_error.dart](https://github.com/WildanFrananda/kinetix-courier-mobile/blob/29a96d33884f3ee9ff2831043e34aee2da235088/lib/services/auth/identity_error.dart#L52-L74),
[sign_in_delay_mixin.dart](https://github.com/WildanFrananda/kinetix-courier-mobile/blob/29a96d33884f3ee9ff2831043e34aee2da235088/lib/mixins/sign_in_delay_mixin.dart#L7-L54),
[login_view_model.dart](https://github.com/WildanFrananda/kinetix-courier-mobile/blob/29a96d33884f3ee9ff2831043e34aee2da235088/lib/viewmodels/login_view_model.dart#L124-L133)).

## 2. Selesaikan autentikasi dua faktor

Hanya bila langkah 1 menjawab `mfaRequired`. Kirim `challengeToken` dari jawaban itu dan enam digit yang tampil
di aplikasi authenticator kurir, dalam `expiresIn` detik sejak langkah 1. Aplikasi kurir mencatat batas waktu itu
saat challenge tiba, dan setelah batasnya lewat meminta kurir masuk lagi alih-alih mengirim kodenya
([login_view_model.dart](https://github.com/WildanFrananda/kinetix-courier-mobile/blob/29a96d33884f3ee9ff2831043e34aee2da235088/lib/viewmodels/login_view_model.dart#L70-L83),
[#L114-L122](https://github.com/WildanFrananda/kinetix-courier-mobile/blob/29a96d33884f3ee9ff2831043e34aee2da235088/lib/viewmodels/login_view_model.dart#L114-L122)).
Aplikasi mengirim dua header yang sama seperti di langkah 1, dan menunggu jawaban `429` dengan cara yang sama,
sambil tetap memegang challenge-nya. Jawaban `401` dengan `WRONG_CODE` membiarkan challenge tetap terbuka:
aplikasi kurir menampilkan penolakannya dan menerima kode berikutnya. Setelah `401` lainnya, challenge itu tidak
akan pernah berhasil: aplikasi kurir membuangnya dan meminta password lagi. Aplikasi mengenali `WRONG_CODE` dari
`message`-nya, `That code is not valid`
([session_repository_impl.dart](https://github.com/WildanFrananda/kinetix-courier-mobile/blob/29a96d33884f3ee9ff2831043e34aee2da235088/lib/repositories/session_repository_impl.dart#L394-L404),
[identity_error.dart](https://github.com/WildanFrananda/kinetix-courier-mobile/blob/29a96d33884f3ee9ff2831043e34aee2da235088/lib/services/auth/identity_error.dart#L76-L79),
[login_view_model.dart](https://github.com/WildanFrananda/kinetix-courier-mobile/blob/29a96d33884f3ee9ff2831043e34aee2da235088/lib/viewmodels/login_view_model.dart#L162-L169)).
Jawaban `200` membawa pasangan token yang sama seperti masuk tanpa faktor kedua; lanjut ke langkah 3. Saat itu
challenge-nya sudah terpakai, jadi jawaban `200` yang tidak bisa dibaca aplikasi kurir mengembalikan kurir ke
langkah password
([session_repository_impl.dart](https://github.com/WildanFrananda/kinetix-courier-mobile/blob/29a96d33884f3ee9ff2831043e34aee2da235088/lib/repositories/session_repository_impl.dart#L157-L195)).

## 3. Baca data kurir

Kirim access token dari langkah 1 atau langkah 2. `data.id` adalah driver id: channel kurir di driver socket
adalah `driver:<data.id>`. Jawaban `403` dengan `pending_approval` berarti admin belum menyetujui kurir itu, dan
`404` berarti akunnya belum mendaftarkan kendaraan; [registrasi](/id/apis/rest/courier-app/register/) membahas
keduanya. Aplikasi kurir menentukan apa yang disimpannya dari jawaban ini
([session_repository_impl.dart](https://github.com/WildanFrananda/kinetix-courier-mobile/blob/29a96d33884f3ee9ff2831043e34aee2da235088/lib/repositories/session_repository_impl.dart#L316-L354)):

- pada `200`, aplikasi menyimpan pasangan token bersama `data.id`, lalu membuka socket;
- pada `403` `pending_approval`, aplikasi menyimpan pasangan token tanpa driver id dan menampilkan layar tunggu;
  pembacaan data ini berikutnya setelah disetujui akan mengisi id-nya;
- pada jawaban lain, atau bila tidak ada jawaban, aplikasi mengirim pasangan baru itu ke
  [keluar](/id/apis/rest/courier-app/stay-signed-in/), menunggu paling lama lima detik, dan tidak menyimpan apa
  pun, sehingga tidak ada refresh token yang masih berlaku di server tetapi terlupakan di ponsel.
