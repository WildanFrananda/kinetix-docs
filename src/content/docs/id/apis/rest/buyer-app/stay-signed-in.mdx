Access token kedaluwarsa `expiresIn` detik setelah identity menerbitkannya. Aplikasi pembeli yang memegang
session dari [Daftar dan masuk](/id/apis/rest/buyer-app/sign-up-and-sign-in/) menjaganya tetap hidup dengan
menukar refresh token-nya (langkah 1) setiap kali access token habis. Ketika pembeli keluar, aplikasi lebih
dulu menghentikan push notification ke ponselnya (langkah 2), lalu mengakhiri session di identity (langkah 3).
Kedua token dijelaskan di [ikhtisar](/id/apis/rest/#token).

## 1. Refresh pasangan token

Aplikasi melakukan refresh begitu `expiresIn` detik sudah lewat, atau ketika sebuah request ditolak dengan
`401` dan `exp` milik access token sudah lewat, lalu mengulang request itu dengan access token yang baru.
`401` selagi token masih berlaku tidak diselesaikan dengan refresh: endpoint dua faktor milik identity,
misalnya, menjawab password yang salah dengan `401`
([Autentikasi dua faktor](/id/apis/rest/buyer-app/two-factor/)). Seperti saat masuk, refresh tidak membawa
`X-Kinetix-Client`: session yang dimulai tanpa header itu diperpanjang tanpa header itu pula. Pada `200`,
aplikasi mengganti kedua token yang tersimpan sekaligus. Refresh token berotasi: setiap penukaran
menghabiskan token yang dikirim, dan token yang sudah terpakai bila dikirim lagi dianggap dicuri, sehingga
seluruh session berakhir
([token.service.ts](https://github.com/WildanFrananda/kinetix-identity-service/blob/4193caf69b2ebea67534e619ebf3a2ccc384e857/src/application/services/token.service.ts#L268-L324)).
Karena itu aplikasi tidak pernah mengirim refresh token dua kali, dan tidak pernah dalam dua request
sekaligus: request yang mendapati access token kedaluwarsa selagi refresh sedang berjalan menunggu refresh
itu, bukan memulai refresh sendiri. `401` di sini berarti session sudah berakhir: pembeli masuk lagi.

## 2. Melupakan ponsel untuk push

Bila aplikasi pernah mendaftarkan ponsel untuk push notification, aplikasi melupakan ponsel itu sekarang,
selagi masih memegang access token yang dibutuhkan panggilan itu: langkah 5 di
[Push notification](/id/apis/rest/buyer-app/push-notifications/#5-melupakan-ponsel). Aplikasi yang tidak
pernah mendaftarkan ponselnya langsung ke langkah 3.

## 3. Keluar

Aplikasi mengirim access token-nya dan, di body, `refreshToken` milik session ini. identity lalu mencabut
access token itu dan mengakhiri session ini saja. Bila field itu dihilangkan, identity mengakhiri semua session
akun itu, di semua perangkat tempat pembeli masuk; `null` ditolak, bukan dibaca dengan cara itu
([auth_usecase.service.ts](https://github.com/WildanFrananda/kinetix-identity-service/blob/4193caf69b2ebea67534e619ebf3a2ccc384e857/src/application/services/auth_usecase.service.ts#L212-L223),
[token.service.ts](https://github.com/WildanFrananda/kinetix-identity-service/blob/4193caf69b2ebea67534e619ebf3a2ccc384e857/src/application/services/token.service.ts#L326-L333)).
Kong memeriksa access token di route ini, jadi token yang kedaluwarsa ditolak sebelum sampai ke identity:
aplikasi melakukan refresh (langkah 1) lalu keluar dengan pasangan yang baru. Setelah `204`, aplikasi membuang
kedua token.
