order menjawab order-order yang pembelinya adalah `sub` milik access token. Aplikasi pembeli mendaftarnya
(langkah 1), membuka salah satunya (langkah 2), dan melacak pengantaran aktif secara live lewat WebSocket (langkah 3).
Order yang dibuat [checkout](/id/apis/rest/buyer-app/checkout/) dibaca dengan cara yang sama.

## 1. Mendaftar order

Terbaru lebih dulu, dan order yang dibuat pada saat yang sama diurutkan menurut `id`, jadi setiap order punya
satu tempat di daftar
([OrderService.cs](https://github.com/WildanFrananda/kinetix-order-service/blob/a0167a3ec43e857e85401924b4bee486e596d4fd/Application/Services/OrderService.cs#L637-L642)).
`status` menyempitkan daftar ke satu status. Aplikasi meminta `page` berikutnya selama `page` × `pageSize` masih
di bawah `totalCount`, sampai `page` 10.000, halaman terakhir yang dilayani order (`maxPage`). Halaman dipotong
menurut posisi, jadi order yang dibuat selagi aplikasi berpindah halaman membuat halaman berikutnya mengulang
order yang sudah ditampilkan: aplikasi membuang yang berulang menurut `id`, dan membaca halaman 1 lagi untuk
menampilkan order yang dibuat sejak itu. `id` setiap item membuka order-nya di langkah 2.

<RestEndpoint id="order.listMyOrders" />

## 2. Membaca satu order

`{orderId}` adalah `id` sebuah item dari langkah 1, atau `id` dari jawaban checkout; `orderNumber` tidak
diterima di sini. Jawabannya menunjukkan `status` order, baris-barisnya dan jumlah uangnya, serta
`driverPrincipalId` begitu seorang kurir sudah mengantarnya. Order yang sudah terkirim bisa
[diulas](/id/apis/rest/buyer-app/reviews/), dan riwayatnya
[dibuktikan](/id/apis/rest/buyer-app/proofs/#5-mengambil-evidence-order).

## 3. Lacak posisi kurir secara live

Saat sebuah order sudah di-assign atau diambil kurir, aplikasi pembeli membuka socket event terpadu di
`wss://api.wildanfrananda.my.id/ws/v1/events` dengan access token Bearer-nya
([event_socket.tl](https://github.com/WildanFrananda/kinetix-edge-service/blob/8c0fa9447c9d9fea964540ed1f8d032a3341b702/src/http/event_socket.tl#L601-L630)).
Berbeda dari kurir dan seller, pembeli hanya tersambung ke edge — tidak ada socket upstream yang dibuka ke matching
([#L331-L334](https://github.com/WildanFrananda/kinetix-edge-service/blob/8c0fa9447c9d9fea964540ed1f8d032a3341b702/src/http/event_socket.tl#L331-L334)).

<RestSocket id="edge.buyerSocket" />

Kirim `subscription.subscribe` dengan `id` order dari langkah 1 atau 2 (UUID `orderId`). Edge memanggil order
`GET /api/v1/orders/{orderId}` memakai token pembeli untuk memastikan kepemilikan dan mengambil `orderNumber`, lalu
men-subscribe channel Redis Pub/Sub milik matching untuk nomor order itu
([#L222-L305](https://github.com/WildanFrananda/kinetix-edge-service/blob/8c0fa9447c9d9fea964540ed1f8d032a3341b702/src/http/event_socket.tl#L222-L305)).
