Semua yang diminta browser, integrasi, atau aplikasi kurir dari Kinetix tiba di satu tempat: Kong, yang
berjalan tanpa database, dengan seluruh konfigurasinya ditulis dalam
[Pkl](https://github.com/WildanFrananda/kinetix-api-gateway/blob/5c31fc4d53c22d0427c72491c2f72bb68c1b5ed7/config/gateway.pkl)
lalu dirender ke format deklaratif Kong. Halaman ini diperiksa terhadap gateway
[v1.14.0](https://github.com/WildanFrananda/kinetix-api-gateway/tree/5c31fc4d53c22d0427c72491c2f72bb68c1b5ed7),
versi yang berjalan di production, di atas
[Kong 3.9.4](https://github.com/Kong/kong/tree/ddc85be461165c9eb4506669343aa0d0c627e687), versi yang dibawa
[digest yang dipin](https://github.com/WildanFrananda/kinetix-api-gateway/blob/5c31fc4d53c22d0427c72491c2f72bb68c1b5ed7/Dockerfile#L92-L95)
oleh image-nya. Apa yang dikirim client dan apa yang ia terima ada di [referensi REST](/id/apis/rest/); halaman
ini membahas mengapa gateway dibangun seperti ini.

## Host

Kong menjawab tiga host publik dan dua alamat backoffice yang tidak dipublikasikan, dan masing-masing melayani
hal yang berbeda:

- **`api.wildanfrananda.my.id`** melayani API: setiap route di bawah `/api/v1/`, signing key identity, dua
  WebSocket milik matching, dan dua jawaban yang diberikan Kong sendiri.
- **`storage.wildanfrananda.my.id`** menyimpan file yang diunggah. Setiap path di sana diteruskan ke object store,
  [dengan header `Host` dipertahankan dan 16 MB per request](https://github.com/WildanFrananda/kinetix-api-gateway/blob/5c31fc4d53c22d0427c72491c2f72bb68c1b5ed7/config/gateway.pkl#L566-L588):
  URL unggahan ditandatangani atas host yang dikirim ponsel, sehingga host yang ditulis ulang akan menggagalkan
  setiap tanda tangan.
- **`seller.wildanfrananda.my.id`** adalah host aplikasi web penjual. Di sana Kong mengirim
  [`/bff/` beserta semua yang ada di bawahnya ke edge](https://github.com/WildanFrananda/kinetix-api-gateway/blob/5c31fc4d53c22d0427c72491c2f72bb68c1b5ed7/config/gateway.pkl#L284-L290),
  dengan path dan `Host` tidak diubah, agar [edge](/id/services/edge/) bisa membedakan app dari host-nya.
  [Setiap path lain di host itu](https://github.com/WildanFrananda/kinetix-api-gateway/blob/5c31fc4d53c22d0427c72491c2f72bb68c1b5ed7/config/gateway.pkl#L292-L298)
  dijawab Kong dengan
  [`404 Not found`](https://github.com/WildanFrananda/kinetix-api-gateway/blob/5c31fc4d53c22d0427c72491c2f72bb68c1b5ed7/config/gateway.pkl#L212-L218),
  termasuk `/api/v1/`.
- **Backoffice** tidak punya host publik. Staf menjangkaunya di dua alamat yang tidak dipublikasikan: onion service
  Tor, yang masuk ke Kong lewat [listener-listener-nya sendiri](#tls-di-luar-dan-listener-di-dalam), dan alamat di
  jaringan staf Kinetix di balik [gerbang staf](#gerbang-staf). Kong menyajikan kepada masing-masing
  [sertifikatnya sendiri](https://github.com/WildanFrananda/kinetix-api-gateway/blob/5c31fc4d53c22d0427c72491c2f72bb68c1b5ed7/config/gateway.pkl#L802-L820), dipilih menurut nama yang diminta browser. Di
  keduanya, Kong mengirim [`/bff/` ke edge](https://github.com/WildanFrananda/kinetix-api-gateway/blob/5c31fc4d53c22d0427c72491c2f72bb68c1b5ed7/config/gateway.pkl#L268-L282) dengan `Host` tidak diubah, dan
  [setiap path lain ke aplikasi statis backoffice](https://github.com/WildanFrananda/kinetix-api-gateway/blob/5c31fc4d53c22d0427c72491c2f72bb68c1b5ed7/config/gateway.pkl#L302-L338), dengan tile peta di bawah
  `/tiles/` di route tersendiri yang batasnya lebih besar ([Batas, label, dan hitungan](#batas-label-dan-hitungan)).

Aturan terakhir untuk web penjual itu lebih penting daripada kelihatannya. Route API tidak menyebut host, jadi
tanpa aturan itu route tersebut akan menjawab juga di host web penjual, dan jawaban API yang disajikan di bawah
origin sebuah web app adalah konten di origin yang memegang cookie sesi app itu. Di alamat backoffice, route milik
aplikasinya sendiri mengambil setiap path di luar `/bff/` dengan alasan yang sama. Web app hanya menjangkau API
lewat `/bff/`, tempat edge memutuskan apa yang diteruskan. [Referensi REST](/id/apis/rest/#alamat-dan-transport) memberikan setiap host
beserta contoh request.

## TLS di luar, dan listener di dalam

Gateway punya
[empat listener](https://github.com/WildanFrananda/kinetix-api-gateway/blob/5c31fc4d53c22d0427c72491c2f72bb68c1b5ed7/Dockerfile#L118-L123),
dan hanya satu yang menghadap internet: listener yang melayani host-host publik, lewat TLS. Tidak ada yang menjawab HTTP biasa dari luar: port yang
masih menjawab plaintext adalah port yang terus dipakai client, dan setiap token yang diperiksa gateway akan
melintasi jaringan tanpa enkripsi dalam perjalanan untuk diperiksa. Container-nya
[menolak start tanpa sertifikat](https://github.com/WildanFrananda/kinetix-api-gateway/blob/5c31fc4d53c22d0427c72491c2f72bb68c1b5ed7/bin/entrypoint.sh#L214-L218).
Jadi client selalu memakai `https://`, dan WebSocket dari client selalu `wss://`.

Listener kedua hanya ada di dalam jaringan Kinetix, dan hanya edge yang memakainya: ketika panggilan web app di
bawah `/bff/api/` harus sampai ke sebuah service, atau web penjual membuka socket-nya, edge mengirimnya ke sana.
Setiap route API ditulis sekali dan
[dirender dua kali](https://github.com/WildanFrananda/kinetix-api-gateway/blob/5c31fc4d53c22d0427c72491c2f72bb68c1b5ed7/config/gateway.pkl#L170-L200):
route yang dilayani listener TLS, dan kembarannya dengan path, method, service, penulisan ulang path, dan
pemeriksaan token yang sama, yang dilayani listener internal.
[Penjaga di setiap kembaran](https://github.com/WildanFrananda/kinetix-api-gateway/blob/5c31fc4d53c22d0427c72491c2f72bb68c1b5ed7/config/gateway.pkl#L152-L159)
menolak request yang tidak tiba sebagai HTTP biasa di listener itu, dengan membaca koneksinya, bukan header,
sehingga request dari luar yang menyebut host sebuah kembaran ditolak sebelum hal lain dijalankan.

Kembaran tidak membawa gerbang staf maupun rate limit. Lawan bicaranya selalu edge, jadi keduanya akan melihat
alamat edge sebagai ganti alamat browser: gerbang akan menolak setiap admin, dan semua pengguna web akan berbagi
satu jatah. Alamat browser sendiri diperiksa di tempat browser masuk, di `/bff/`. `/health`, `security.txt`,
socket kurir, host storage, dan `/bff/` sendiri tidak punya kembaran; socket merchant milik matching punya satu,
untuk edge, seperti dijelaskan [WebSocket](#websocket). Di belakang setiap listener, di dalam jaringan
privat, Kong menjangkau setiap service lewat HTTP biasa. Panggilan antar-service menempuh jalan yang sama sekali
lain: gRPC di atas mutual TLS, yang dijelaskan di [Siapa yang memanggil?](/id/learn/who-is-calling/).

Dua listener lainnya hanya ada untuk onion service backoffice. Tor membawa koneksi browser, terenkripsi dan
terautentikasi dari ujung ke ujung, ke sebuah proses Tor di dalam jaringan Kinetix, yang menyerahkannya ke salah
satunya; tidak ada apa pun dari luar jaringan itu yang menjangkau port keduanya. HTTPS tiba di listener yang
berbicara TLS, tempat Kong menyajikan sertifikat alamat onion. HTTP biasa tiba di listener satunya dan hanya
dialihkan, `308` ke path dan query yang sama lewat `https://`, tanpa ada yang diteruskan. Tor sudah mengenkripsi
koneksinya, jadi TLS tidak menambah kerahasiaan di sini;
[TLS ada untuk perangkat lunak yang hanya memercayai origin `https://`](https://github.com/WildanFrananda/kinetix-api-gateway/blob/5c31fc4d53c22d0427c72491c2f72bb68c1b5ed7/CLAUDE.md#L297-L300): lewat HTTP
biasa, browser di alamat onion bisa menolak passkey dan cookie `Secure` milik session. Tiga route onion milik
backoffice menjawab alamat onion, masing-masing di balik [penjaga sejenis](https://github.com/WildanFrananda/kinetix-api-gateway/blob/5c31fc4d53c22d0427c72491c2f72bb68c1b5ed7/config/gateway.pkl#L161-L168),
yang melayani HTTPS di listener TLS milik onion, mengalihkan HTTP biasa di listener satunya, dan menolak selain itu
dengan `421`, termasuk alamat onion yang disebut di listener TLS publik. Di listener HTTP biasa tidak ada yang lain
yang menjawab. Kong tidak bisa membedakan kedua listener TLS-nya, jadi request di listener milik onion yang menyebut
host lain [dijawab seperti di listener publik](https://github.com/WildanFrananda/kinetix-api-gateway/blob/5c31fc4d53c22d0427c72491c2f72bb68c1b5ed7/CLAUDE.md#L342-L348), tanpa apa pun yang belum publik di sana.
Route onion membawa rate limit tetapi tidak membawa gerbang staf: peer-nya selalu proses Tor, dan otorisasi klien
Tor sudah memutuskan siapa yang boleh tersambung.

## Ke mana setiap path pergi

Dihasilkan dari data terverifikasi yang sama dengan [peta sistem](/id/architecture/system-map/):

Sebuah route adalah prefix path. Kebanyakan service menerima path persis seperti yang dikirim client;
sebagian kecil prefix-nya diubah ke milik service itu — `/api/v1/products` milik catalog tiba sebagai
[`/api/products`](https://github.com/WildanFrananda/kinetix-api-gateway/blob/5c31fc4d53c22d0427c72491c2f72bb68c1b5ed7/config/gateway.pkl#L391-L401),
`/api/v1/warehouse` milik warehouse sebagai
[`/api/v1`](https://github.com/WildanFrananda/kinetix-api-gateway/blob/5c31fc4d53c22d0427c72491c2f72bb68c1b5ed7/config/gateway.pkl#L438-L448).
`/bff/` hanya dirutekan di host dua web app.

Tiga hal lagi yang dilayani Kong tidak ada di peta:

- `/health` dan `/.well-known/security.txt`, yang
  [dijawab Kong sendiri](https://github.com/WildanFrananda/kinetix-api-gateway/blob/5c31fc4d53c22d0427c72491c2f72bb68c1b5ed7/config/gateway.pkl#L223-L260)
  tanpa menyentuh service mana pun. `/health` hanya berkata `{"status":"ok"}`; `security.txt` adalah
  [kontak RFC 9116](https://github.com/WildanFrananda/kinetix-api-gateway/blob/5c31fc4d53c22d0427c72491c2f72bb68c1b5ed7/config/gateway.pkl#L86-L93)
  yang menunjuk ke [cara melaporkan kerentanan](/id/reference/report-a-vulnerability/).
- Notifikasi dari penyedia pembayaran,
  [hanya `POST`](https://github.com/WildanFrananda/kinetix-api-gateway/blob/5c31fc4d53c22d0427c72491c2f72bb68c1b5ed7/config/gateway.pkl#L646-L662).
  Notifikasi itu tidak membawa token, karena penyedianya memang tidak punya token untuk dikirim; payment
  memverifikasi tanda tangan setiap notifikasi sebagai gantinya, seperti dijelaskan di
  [halaman payment](/id/services/payment/).
- Host storage, yang setiap path-nya diteruskan ke object store.

## WebSocket

Dua socket, keduanya dilayani matching:
[`/ws/v1/matching/driver` dan `/ws/v1/matching/merchant`](https://github.com/WildanFrananda/kinetix-api-gateway/blob/5c31fc4d53c22d0427c72491c2f72bb68c1b5ed7/config/gateway.pkl#L534-L564),
masing-masing juga dengan `/websocket` di belakangnya, bentuk yang dipanggil client JavaScript Phoenix. WebSocket
dimulai sebagai request HTTP biasa yang meminta upgrade, jadi Kong merutekannya seperti request lain lalu
meneruskan koneksi yang sudah di-upgrade. Access token ikut bersama request koneksi, dan matching memeriksanya
sebelum socket terbuka —
[token kurir atau admin untuk socket driver](https://github.com/WildanFrananda/kinetix-matching-service/blob/7ef67a0ca1d0e8945f638de8a2f9684e84d06886/lib/fleet_pulse_web/channels/driver_socket.ex#L27-L49),
[token seller atau admin untuk socket merchant](https://github.com/WildanFrananda/kinetix-matching-service/blob/7ef67a0ca1d0e8945f638de8a2f9684e84d06886/lib/fleet_pulse_web/channels/merchant_socket.ex#L24-L45).
Request tanpa token, atau dengan token yang buruk, ditolak dengan `403`, request yang tidak bisa diperiksa
matching karena identity tidak terjangkau ditolak dengan `503`, dan socket tidak dibuka. Socket aplikasi kurir
dijelaskan langkah demi langkah di [Mulai bertugas dan mengantar](/id/apis/rest/courier-app/deliver/).

### Kembaran socket merchant

Web penjual tidak memegang token, jadi ia tidak bisa membuka socket merchant di host API seperti aplikasi kurir
membuka socket-nya sendiri. Ia meminta edge, di host-nya sendiri, dan edge membukakan socket ke matching untuknya
dengan access token milik sesi, seperti dijelaskan [edge](/id/services/edge/#socket-merchant-milik-web-penjual).
Koneksi itu lewat listener internal, jadi route socket merchant
[ditulis seperti route API](https://github.com/WildanFrananda/kinetix-api-gateway/blob/5c31fc4d53c22d0427c72491c2f72bb68c1b5ed7/config/gateway.pkl#L549-L564)
dan dirender dengan kembaran: dua path yang sama dan service yang sama, penjaga di urutan pertama, dan tanpa
gerbang staf, rate limit, maupun pemeriksaan token di Kong, karena matching memeriksa token dan role-nya sendiri.
Kong meneruskan upgrade lewat route HTTP biasa sama seperti lewat route TLS, jadi
[kembaran itu tidak memerlukan apa pun yang tidak dimiliki kembaran API](https://github.com/WildanFrananda/kinetix-api-gateway/blob/5c31fc4d53c22d0427c72491c2f72bb68c1b5ed7/CLAUDE.md#L271-L278).

Kembaran itu tetap di dalam dengan cara yang sama seperti setiap kembaran.
[Ia hanya menyebut host internal gateway, lewat HTTP biasa](https://github.com/WildanFrananda/kinetix-api-gateway/blob/5c31fc4d53c22d0427c72491c2f72bb68c1b5ed7/config/gateway.pkl#L181-L196),
dan penjaganya menolak dengan `421` apa pun yang tidak tiba sebagai HTTP biasa di listener internal, yang tidak
bisa dijangkau dari luar jaringan Kinetix. Request HTTP biasa ke path yang sama yang menyebut host lain tidak
cocok dengan kembaran mana pun dan mendapat `426` dari Kong. Socket kurir sama sekali tidak punya kembaran:
aplikasi kurir memanggil listener TLS.

### Sembilan puluh detik untuk socket yang diam

Phoenix
[menutup socket yang tidak menerima apa pun selama 60 detik](https://github.com/phoenixframework/phoenix/blob/b5026660dc744424545e7d2e3b7547507443ab40/lib/phoenix/endpoint.ex#L1044-L1045),
dan client JavaScript-nya
[mengirim heartbeat setiap 30 detik](https://github.com/phoenixframework/phoenix/blob/b5026660dc744424545e7d2e3b7547507443ab40/assets/js/phoenix/socket.js#L174).
Edge menunggu
[90 detik](https://github.com/WildanFrananda/kinetix-edge-service/blob/0a52d5805b57a818b16b05848b8333d34115f682/nginx/nginx.conf#L102-L105)
pada socket merchant yang diam, agar proxy tidak pernah menjadi pihak yang mengakhiri socket yang masih dipegang
Phoenix. Secara default, Kong
[menyerah setelah 60 detik](https://github.com/Kong/kong/blob/ddc85be461165c9eb4506669343aa0d0c627e687/kong/db/schema/entities/services.lua#L40-L42)
tanpa membaca dari atau menulis ke sebuah service, dan socket web penjual melewati Kong dua kali: di `/bff/`,
antara browser dan edge, dan di kembaran, antara edge dan matching. Dengan default itu, Kong akan menutup socket
yang diam sebelum salah satu ujungnya bermaksud begitu. Karena itu dua service Kong di jalur itu, milik edge, yang
menerima `/bff/` di host kedua web app, dan milik socket merchant, yang menerima route publiknya dan kembarannya,
membaca dan menulis selama 90 detik
([milik edge](https://github.com/WildanFrananda/kinetix-api-gateway/blob/5c31fc4d53c22d0427c72491c2f72bb68c1b5ed7/config/gateway.pkl#L262-L266),
[milik socket](https://github.com/WildanFrananda/kinetix-api-gateway/blob/5c31fc4d53c22d0427c72491c2f72bb68c1b5ed7/config/gateway.pkl#L549-L553)).
Koneksi awal tetap timeout pada default Kong, dan setiap service lain tetap memakai default Kong. Harganya
dibayar ketika sesuatu macet: panggilan `/bff/` atau socket merchant, termasuk route publiknya, yang tidak
mendengar apa pun kini menunggu 90 detik untuk `504` atau penutupan dari Kong, bukan 60.

## Kunci pertama untuk token

Di enam kelompok route — route identity yang memerlukan login, REST API matching, payment, notary,
pendaftaran handset di notification, serta credential kurir dan penulisan predicate milik seal — Kong
[memeriksa access token sebelum request diteruskan](https://github.com/WildanFrananda/kinetix-api-gateway/blob/5c31fc4d53c22d0427c72491c2f72bb68c1b5ed7/config/gateway.pkl#L95-L104).
Ia mengenal
[satu penanda tangan: identity, lewat issuer-nya, dengan public key identity dan RS256](https://github.com/WildanFrananda/kinetix-api-gateway/blob/5c31fc4d53c22d0427c72491c2f72bb68c1b5ed7/config/gateway.pkl#L788-L800),
dan memeriksa tanda tangan serta bahwa token belum kedaluwarsa. Token dari pihak lain, tanpa tanda
tangan, atau ditandatangani dengan algoritma lain ditolak di pintu dengan `401`.

Kong membaca token dari `Authorization` dan tidak dari tempat lain. Plugin `jwt`-nya
[mencari token di query string, di cookie, dan di header](https://github.com/Kong/kong/blob/ddc85be461165c9eb4506669343aa0d0c627e687/kong/plugins/jwt/handler.lua#L22-L80),
dan
[default-nya membaca parameter query bernama `jwt`](https://github.com/Kong/kong/blob/ddc85be461165c9eb4506669343aa0d0c627e687/kong/plugins/jwt/schema.lua#L12-L23).
Token di dalam URL berakhir di access log, di riwayat browser, dan di `Referer` halaman berikutnya, jadi
[Kinetix tidak menyebut parameter query maupun cookie apa pun](https://github.com/WildanFrananda/kinetix-api-gateway/blob/5c31fc4d53c22d0427c72491c2f72bb68c1b5ed7/config/gateway.pkl#L100-L101).
Token yang dikirim di mana pun selain `Authorization: Bearer …` dianggap tidak ada, dan request-nya
mendapat
[`401` dengan `{"message":"Unauthorized"}`](https://github.com/Kong/kong/blob/ddc85be461165c9eb4506669343aa0d0c627e687/kong/plugins/jwt/handler.lua#L160-L166)
sebelum meninggalkan gateway. Socket tidak membawa pemeriksaan token Kong: matching membaca token-nya sendiri.

Itu kunci pertama, bukan satu-satunya. Kong tidak menanyakan apakah token itu access token atau refresh
token, atau untuk audience mana token itu diterbitkan; service di belakangnya yang menanyakan, terhadap
key yang dipublikasikan identity, lalu memutuskan apa yang boleh dilakukan pemanggil. Route tanpa
pemeriksaan Kong — login dan registrasi, signing key identity, pencarian produk, katalog, keranjang dan
order, ulasan, warehouse, pricing, dan route seal lainnya — entah memang publik secara rancangan atau diperiksa oleh service
itu sendiri; setiap [halaman service](/id/services/order/) menyebutkan yang mana. `/bff/` sama sekali tidak
membawa token: browser mengirim cookie, dan edge yang memegang token.

## Gerbang staf

Route yang hanya boleh dipanggil admin hanya menjawab jaringan staf Kinetix. Masing-masing punya route sendiri
yang membawa
[`ip-restriction`](https://github.com/WildanFrananda/kinetix-api-gateway/blob/5c31fc4d53c22d0427c72491c2f72bb68c1b5ed7/config/gateway.pkl#L106-L113)
milik Kong, yang hanya menerima rentang alamat yang disebut environment saat container start:

- daftar pengajuan seller dan kurir di identity beserta hitungannya, serta menyetujui atau menolak sebuah pengajuan
  ([gateway.pkl](https://github.com/WildanFrananda/kinetix-api-gateway/blob/5c31fc4d53c22d0427c72491c2f72bb68c1b5ed7/config/gateway.pkl#L374-L387));
- penulisan kategori di catalog; membaca kategori tetap publik
  ([gateway.pkl](https://github.com/WildanFrananda/kinetix-api-gateway/blob/5c31fc4d53c22d0427c72491c2f72bb68c1b5ed7/config/gateway.pkl#L428-L434));
- bin, penerimaan stok, dan penyesuaian stok di warehouse
  ([gateway.pkl](https://github.com/WildanFrananda/kinetix-api-gateway/blob/5c31fc4d53c22d0427c72491c2f72bb68c1b5ed7/config/gateway.pkl#L450-L487));
- driver dan API backoffice milik matching
  ([gateway.pkl](https://github.com/WildanFrananda/kinetix-api-gateway/blob/5c31fc4d53c22d0427c72491c2f72bb68c1b5ed7/config/gateway.pkl#L502-L532));
- pencarian order, saga-nya, retur yang perlu perhatian, menolak retur, dan menyelesaikan order
  ([gateway.pkl](https://github.com/WildanFrananda/kinetix-api-gateway/blob/5c31fc4d53c22d0427c72491c2f72bb68c1b5ed7/config/gateway.pkl#L615-L626));
- penulisan predicate milik seal, yaitu menyetujui dan menarik sebuah predicate; membaca predicate tetap publik
  ([gateway.pkl](https://github.com/WildanFrananda/kinetix-api-gateway/blob/5c31fc4d53c22d0427c72491c2f72bb68c1b5ed7/config/gateway.pkl#L760-L769));
- dan seluruh backoffice di alamat jaringan stafnya: aplikasinya, tile petanya, dan setiap panggilan di bawah
  `/bff/`, termasuk login
  ([gateway.pkl](https://github.com/WildanFrananda/kinetix-api-gateway/blob/5c31fc4d53c22d0427c72491c2f72bb68c1b5ed7/config/gateway.pkl#L268-L275), [L306-L323](https://github.com/WildanFrananda/kinetix-api-gateway/blob/5c31fc4d53c22d0427c72491c2f72bb68c1b5ed7/config/gateway.pkl#L306-L323)).
  Onion service-nya tidak punya gerbang staf: di sana, otorisasi klien Tor yang memutuskan siapa yang tersambung.

Gerbang itu membaca
[alamat koneksi](https://github.com/Kong/kong/blob/ddc85be461165c9eb4506669343aa0d0c627e687/kong/plugins/ip-restriction/handler.lua#L67-L92),
bukan header yang bisa ditulis client, dan pihak lain mendapat `403` dengan pesan tetap yang tidak mengulang
alamat pemanggil. Di route admin milik identity, matching, dan seal,
[pemeriksaan token Kong berjalan lebih dulu](https://github.com/WildanFrananda/kinetix-api-gateway/blob/5c31fc4d53c22d0427c72491c2f72bb68c1b5ed7/CLAUDE.md#L99-L104),
jadi request tanpa token yang sah mendapat `401` sebelum gerbang ditanya.

Gerbang itu adalah kunci kedua di belakang pemeriksaan role milik service sendiri, bukan penggantinya.
[Endpoint yang boleh dipanggil pengguna maupun admin](https://github.com/WildanFrananda/kinetix-api-gateway/blob/5c31fc4d53c22d0427c72491c2f72bb68c1b5ed7/CLAUDE.md#L71-L74),
seperti membaca pengajuan seorang seller, tidak dipagari: jaringan tidak bisa membedakan kedua pemanggil itu,
jadi service yang memutuskan. Rentangnya sendiri adalah konfigurasi, bukan kode;
[container menolak start tanpa rentang itu](https://github.com/WildanFrananda/kinetix-api-gateway/blob/5c31fc4d53c22d0427c72491c2f72bb68c1b5ed7/bin/entrypoint.sh#L31-L34),
dan Pkl-nya
[menolak daftar kosong serta rentang yang menerima semua alamat](https://github.com/WildanFrananda/kinetix-api-gateway/blob/5c31fc4d53c22d0427c72491c2f72bb68c1b5ed7/config/gateway.pkl#L16-L18).

## Batas, label, dan hitungan

Setiap request:

- dibatasi, di route yang dilayani listener TLS, sampai
  [100 request per menit dari satu alamat client](https://github.com/WildanFrananda/kinetix-api-gateway/blob/5c31fc4d53c22d0427c72491c2f72bb68c1b5ed7/config/gateway.pkl#L115-L123)
  di setiap route, dihitung di gateway itu sendiri. Batas itu
  [ditambahkan ke setiap route di listener TLS](https://github.com/WildanFrananda/kinetix-api-gateway/blob/5c31fc4d53c22d0427c72491c2f72bb68c1b5ed7/config/gateway.pkl#L173-L179)
  alih-alih sekali untuk seluruh gateway,
  [karena Kong tidak bisa mengecualikan sebuah route dari plugin global](https://github.com/WildanFrananda/kinetix-api-gateway/blob/5c31fc4d53c22d0427c72491c2f72bb68c1b5ed7/CLAUDE.md#L208-L215)
  dan kembaran tidak boleh membawanya; Kong
  [menyimpan hitungan sebuah route di bawah route itu](https://github.com/Kong/kong/blob/ddc85be461165c9eb4506669343aa0d0c627e687/kong/plugins/rate-limiting/policies/init.lua#L68-L73),
  jadi satu alamat punya jatah di setiap route. Satu route adalah sekelompok path milik satu service, dan `/bff/`
  di host sebuah web app adalah satu route: login dari sebuah browser dan semua panggilannya lewat edge berbagi
  jatah itu. Notifikasi penyedia pembayaran punya
  [batasnya sendiri, 600 per menit](https://github.com/WildanFrananda/kinetix-api-gateway/blob/5c31fc4d53c22d0427c72491c2f72bb68c1b5ed7/config/gateway.pkl#L646-L662),
  agar lonjakan pembayaran tidak tercekik oleh batas yang dibuat untuk manusia. Dua route lagi punya batasnya
  sendiri: [route seal yang meneruskan sebuah presentation, 20 per menit](https://github.com/WildanFrananda/kinetix-api-gateway/blob/5c31fc4d53c22d0427c72491c2f72bb68c1b5ed7/config/gateway.pkl#L714-L730), dan
  [tile peta backoffice, 1200 per menit](https://github.com/WildanFrananda/kinetix-api-gateway/blob/5c31fc4d53c22d0427c72491c2f72bb68c1b5ed7/config/gateway.pkl#L125-L129), karena peta mengambil satu tile untuk
  setiap bagian tampilan yang digambarnya, dan
  [route tersendiri menjaga agar peta dan halaman aplikasi tidak saling menghabiskan jatah](https://github.com/WildanFrananda/kinetix-api-gateway/blob/5c31fc4d53c22d0427c72491c2f72bb68c1b5ed7/CLAUDE.md#L419-L422).
  [Referensi REST](/id/apis/rest/#batas)
  mencantumkan path mana yang dihitung bersama;
- membawa [`X-Request-Id`](https://github.com/WildanFrananda/kinetix-api-gateway/blob/5c31fc4d53c22d0427c72491c2f72bb68c1b5ed7/config/gateway.pkl#L823-L830):
  milik client bila ia mengirimnya, UUID baru bila tidak, dan dikembalikan di response agar permintaan
  dukungan bisa menyebut panggilan yang persis;
- [dihitung untuk Prometheus](https://github.com/WildanFrananda/kinetix-api-gateway/blob/5c31fc4d53c22d0427c72491c2f72bb68c1b5ed7/config/gateway.pkl#L831-L840)
  berdasarkan status, latensi, dan kesehatan upstream.

## Browser

Kong menambahkan plugin `cors`-nya ke sebuah route
[hanya bila environment menyebut origin browser](https://github.com/WildanFrananda/kinetix-api-gateway/blob/5c31fc4d53c22d0427c72491c2f72bb68c1b5ed7/config/gateway.pkl#L173-L179),
dan tidak pernah ke `/bff/`
([gateway.pkl](https://github.com/WildanFrananda/kinetix-api-gateway/blob/5c31fc4d53c22d0427c72491c2f72bb68c1b5ed7/config/gateway.pkl#L198-L200)).
Production tidak menyebut satu pun, jadi di production Kong tidak menjawab preflight CORS apa pun dan tidak
menambahkan header `Access-Control-*`. Preflight ke host API diteruskan ke service seperti request lain:
[pemeriksaan token Kong melewati `OPTIONS`](https://github.com/WildanFrananda/kinetix-api-gateway/blob/5c31fc4d53c22d0427c72491c2f72bb68c1b5ed7/config/gateway.pkl#L95-L104).

Web app tidak memerlukan CORS. Sebuah halaman memanggil `/bff/` di host-nya sendiri, origin yang sama dengan
halaman itu, dan edge memanggil API untuknya dengan token yang tidak pernah dilihat halaman; [edge](/id/services/edge/)
menjelaskan alasannya. Aplikasi kurir bukan browser dan tidak mengirim `Origin`.
[Referensi REST](/id/apis/rest/#browser) menjelaskan apa artinya bagi client. Di environment yang memang menyebut
origin, seperti yang bisa dilakukan lab, plugin itu
[tidak pernah mengizinkan credentials](https://github.com/WildanFrananda/kinetix-api-gateway/blob/5c31fc4d53c22d0427c72491c2f72bb68c1b5ed7/config/gateway.pkl#L131-L150),
dan `*` di samping origin bernama
[bahkan tidak bisa dievaluasi](https://github.com/WildanFrananda/kinetix-api-gateway/blob/5c31fc4d53c22d0427c72491c2f72bb68c1b5ed7/config/gateway.pkl#L13-L14).

## Satu image untuk setiap environment

Image-nya membawa Pkl, bukan konfigurasi yang sudah dirender. Saat container start, ia
[merender konfigurasinya](https://github.com/WildanFrananda/kinetix-api-gateway/blob/5c31fc4d53c22d0427c72491c2f72bb68c1b5ed7/bin/entrypoint.sh#L17-L156)
dari nilai milik environment itu sendiri — public key identity, issuer yang dipercaya, origin browser (yang
boleh kosong, tetapi harus dinyatakan), rentang staf, host-host-nya, termasuk alamat onion, dan sertifikat kedua
alamat backoffice, yang masing-masing harus menyebut host-nya — menolak start bila salah satunya tidak ada, lalu
memeriksa bahwa hasilnya memuat key untuk memverifikasi token, gerbang staf, penjaga di setiap kembaran serta di
ketiga route onion, dan dua route tile peta beserta batasnya: gateway tanpa verification key akan merutekan semuanya tanpa mengautentikasi apa pun. Karena itu
digest yang dipindai CI adalah digest yang berjalan di mana-mana.

Setiap perubahan dievaluasi sebelum di-merge.
[CI merender Pkl-nya](https://github.com/WildanFrananda/kinetix-api-gateway/blob/5c31fc4d53c22d0427c72491c2f72bb68c1b5ed7/.github/workflows/ci.yml#L46-L277)
dengan key sekali pakai dan membuktikan bahwa daftar origin kosong tidak menyertakan CORS dan bahwa `*` di
samping origin bernama ditolak; bahwa render tanpa rentang staf, atau dengan rentang yang menerima semua orang,
ditolak, dan bahwa gerbangnya terpasang di dua belas route; bahwa `/bff/` di host dua web app diteruskan ke edge,
`/tiles/` di kedua alamat backoffice ke aplikasinya dengan batas milik peta, sisa host backoffice ke aplikasinya, dan
tidak ada yang lain yang menjawab di sana; bahwa alamat onion punya tepat tiga route berpenjaga, dilayani lewat TLS
dengan sertifikatnya sendiri dan dialihkan dari HTTP biasa; bahwa alamat jaringan staf backoffice adalah sebuah nama,
tidak pernah alamat IP, dengan sertifikatnya sendiri; bahwa setiap route API serta socket merchant punya kembarannya; dan bahwa
[tidak ada plugin `jwt` yang membaca query atau cookie, dan hanya service milik edge dan socket merchant yang menunggu 90 detik](https://github.com/WildanFrananda/kinetix-api-gateway/blob/5c31fc4d53c22d0427c72491c2f72bb68c1b5ed7/test/config_invariants.jq#L56-L66).
Build image
[merendernya sekali lagi](https://github.com/WildanFrananda/kinetix-api-gateway/blob/5c31fc4d53c22d0427c72491c2f72bb68c1b5ed7/Dockerfile#L16-L90),
lalu
[sebuah probe menjalankan image itu sendiri](https://github.com/WildanFrananda/kinetix-api-gateway/blob/5c31fc4d53c22d0427c72491c2f72bb68c1b5ed7/.github/workflows/ci.yml#L313-L317)
dari alamat di dalam dan di luar rentang staf, lewat listener-listener-nya, dan
[mengirim token yang sah di query dan di cookie](https://github.com/WildanFrananda/kinetix-api-gateway/blob/5c31fc4d53c22d0427c72491c2f72bb68c1b5ed7/test/edge_probe/checks.sh#L89-L106)
ke setiap route yang diperiksa Kong, yang harus menjawab seolah request itu tidak membawa token.
